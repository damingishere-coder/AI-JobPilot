# 简历配置稳定性与多格式识别实施任务

## 背景

简历配置页使用严格 API 响应解析，但 Boss 配置接口没有统一的 `success` 字段；同时现有 PDF 仅读取文字层，图片依赖 AI，Word 未支持，解析失败还可能覆盖已保存简历。

## 目标

- 统一 Boss 配置读写响应并消除读取时写数据库的行为。
- 稳定简历配置页启动、档案状态和重试行为。
- 增加 PDF、图片、DOC/DOCX、TXT 的本地预览解析，以 Docling + RapidOCR 为本地底座。
- 对 PDF/图片低质量结果最多执行一次现有 AI 视觉复核，由用户确认预览后再保存。
- 解析失败、AI 结果未知或超限时保留已有简历。

## 允许修改范围

- Boss 配置控制器、服务及其测试。
- 简历解析、AI 图片识别、简历控制器及其测试。
- 简历配置页、Boss 配置页、前端 API 工具、代理配置及针对性测试。
- 项目内 Python 解析器、固定依赖清单、安装脚本和说明文档。

## 禁止修改范围

- 用户数据库内容、已有简历、招聘平台 Cookie、浏览器档案和 `.env`。
- 实际投递、消息发送、外部招聘平台操作。
- 当前主工作树领先远端的五个既有提交。
- Git 历史重写、强推、自动合并或生产服务重启。

## 已确定实现要求

- `/api/boss/config` GET/PUT 使用标准响应 envelope；所有前端调用同步适配。
- 配置读取只读；缺失的“无限”选项只在响应中补齐。
- 本机代理默认使用 `127.0.0.1:8888`，首次快照加载做有界 readiness 等待。
- `POST /api/ai/resume/parse` 仅返回预览，不写数据库；支持 `auto/local/ai_review`。
- `POST /api/ai/resume` 增加 JSON 确认保存，同时保留原 multipart 兼容入口。
- 本地结果做定向 CJK 兼容字符规范化和 0-100 质量评分；低于 85 的 PDF/图片最多 AI 复核一次。
- AI 失败时返回可用的本地结果和警告；本地结果也为空时返回错误，任何失败都不覆盖旧简历。
- 原始文件只在临时目录存在；限制 30MB、PDF 10 页、本地处理 120 秒、输出 200000 字符。

## 验收标准

- Boss 配置页和简历配置页在后端正常时无加载错误；后端暂不可用时提示可重试且不误报无档案。
- PDF、图片、DOC/DOCX、TXT 能生成可编辑预览；康熙部首字符被转换为正常汉字。
- 高质量本地结果不调用 AI；低质量 PDF/图片最多一次；Word 低质量结果提示改传 PDF/图片。
- 预览未确认、解析失败和 AI 失败都不会修改数据库。
- 后端测试、前端针对性测试、lint、typecheck/build 和解析器测试通过。

## 测试命令

- `./gradlew.bat test`
- `pnpm vitest run app/ai-config/page.test.tsx lib/api.test.ts`
- `pnpm lint`
- `pnpm typecheck`
- `pnpm build`
- `python -m unittest discover -s resume-parser -p "test_*.py" -v`

## 返回格式

- 修改文件和关键行为。
- 测试、构建和本地实文件验证证据。
- 分支、提交 SHA、远端 SHA、Push 结果、PR 地址和 CI 状态。
- 回滚方式及未执行的生产切换说明。
