# HR 后端重启后的令牌恢复

## 真实问题与范围

PR155 发布后，后端实际运行 `329115bb76bb64af4cced41a4301976cf4eee900`，数据库与分析队列健康。只读扩展状态证明 1.10.13 保留同一 BOSS 标签与页面，但因 `ACTION_TOKEN_INVALID` 进入 BLOCKED。现有请求代码在 HTTP401 时清除令牌缓存后直接返回失败，托管又把这类启动前的认证拒绝当作不可恢复的业务故障。

只修改 Chrome Bridge：对 HR 接口明确的 HTTP401 / `success=false` / `ACTION_TOKEN_INVALID` 重新取令牌并重试一次。第二次拒绝立即返回；网络断开、发送结果未知、其它认证错误或其它 HTTP 状态都沿用原有不重放规则。失效令牌只清理同一个缓存值，避免并发请求把已经取得的新令牌清掉。

扩展初始化可恢复旧版遗留的令牌阻塞，仅限原启用意图、BLOCKED 与该确切错误码且没有 SEND 检查点。真实用户暂停、发送未知、停用意图、后端持久化暂停和浏览器重启的账号重新确认边界均保留。恢复时只绑定原页面，禁止刷新、导航、重建或抢焦点。

版本为 1.10.14。已有后端部署无需重新启动；浏览器中的扩展必须由用户在 `chrome://extensions` 点击一次“重新加载”才能换成新代码，无需刷新 BOSS 页面。

## 验证

```powershell
node scripts/validate-chrome-extension.mjs
node --test chrome-extension/tests/*.test.cjs
```

新增测试覆盖认证前拒绝的一次重试、重复拒绝的终止、发送未知与网络错误不重放、旧令牌阻塞沿用原页面恢复，以及手动暂停、未知发送、停用意图和远端暂停不被覆盖。完整最终 CI 通过后按正式主线 PR 流程交付。

本地扩展测试 358/358 通过，33 个引用文件和 24 个 JavaScript 脚本校验通过。首次新增远端暂停测试把安全解绑通知也当作了平台动作；纠正为确认只发 UNBIND、没有读取或发送后，全套通过。

## 回滚

通过回滚 PR 撤销本次扩展改动，保留后端 `329115b`、当前有效 Codex 路径及数据库。浏览器扩展回滚同样需要手动重新加载；1.10.13 会再次遇到后端重启后的令牌阻塞，人工恢复可取得新令牌，但不应刷新 BOSS 页面。不能回退数据库或解冻历史 SEND_UNKNOWN。
