# BOSS 本机视觉执行器

该执行器使用现有 Google Chrome 登录窗口，以 Windows UI Automation 读取控件、Windows OCR 核对可见正文，再通过鼠标键盘输入。没有 CDP、DOM 注入、浏览器配置复制、Cookie 导出或自动刷新。后端仍使用现有模型配置与 NapCat QQ 通道。

搜索选中联系人后，若选中行仍在列表视口之外，先核验原生选中行唯一且姓名、公司完整匹配，再使用 UIA ScrollItem 将该行滚入视口；身份仍以重新读取的可见姓名、公司、岗位和正文为准。没有滚动能力、身份冲突或人工接管时保持发送拦截。“处理已发现的全部会话”暂停在 PROCESS 时，可把尚未创建发送任务的读取失败项加入本轮待处理名单，随后恢复整批；不重扫列表、不新增授权、不重发未知步骤。

原生简历选择框同时支持 UIA Dialog 和 BOSS `choose-resume-dialog` 网页容器。只在弹层内核验唯一文件及发送按钮，最多等待弹层 5 秒，确认前再次核对聊天与文件；没有弹层不能当作发送成功。默认扫描模式在发送结果未知时暂停所属单轮批次并保留加密失败现场；下述“处理已发现的全部会话”模式只读锁定未知身份后继续其他联系人。只读复核不点击确认。未知记录不会因升级自动重试。

## 安装与运行

在已有 6866 服务的运行目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File hr-visual/setup.ps1 -Python C:\Python312\python.exe
hr-visual/.venv/Scripts/python.exe -u hr-visual/worker.py --health
```

需要 Windows 交互桌面、中文 OCR、已登录的 Chrome。独立 `.venv` 不改动群报环境。执行时持有与群报一致的 `Local\GroupBrief.WechatDesktopSender` 互斥锁。检测到真人鼠标键盘输入、焦点变化、锁屏或网站验证时停止输入。

焦点暂停的原因会记录实际前台进程名称、当前操作是否观察到物理输入、是否收到取消请求。未观察到物理输入不等于证明无人操作，仍保持暂停；不会自动抢回窗口。该诊断不记录窗口标题、完整进程路径、命令行或地址栏内容。Codex Computer Use 因无法核验浏览器 URL 而停止时，应保留工具阻塞原因并停止真实验收，不刷新 BOSS，也不经项目执行器绕过工具限制。

工作台“本机 Chrome 视觉聊天”选择三个已有会话，核对登录姓名后点击“读取并发送 QQ 建议卡”。档案名与 BOSS 登录姓名不同时需明确勾选本人绑定。普通入口只生成待确认卡；QQ 的详情、修改、发送、跳过、补充、暂停、恢复沿用原操作人及群校验。

`POST /api/hr-assistant/visual/start` 使用现有本机操作令牌，协议为 `2026-09-29-hr-visual-v3`。仅接受三个不同的已有提案及匹配版本。普通请求的 `approved=false`。明确批准的受控测试可传 `approved=true, approvalSource="USER_CONFIRMED_TEST"` 及本次批准的完整正文；原卡缺岗位时还需 `expectedJobName`，原生简历还需 `sendResume=true, resumeSharingConfirmed=true`。这些值作为本次目标的加密授权种子保存，不修改长期授权，消息正文、类型或时间变化即失效。

`GET /api/hr-assistant/visual/status` 返回安装状态、模式、当前运行、阻塞原因和文字/原生简历各自状态。暂停/恢复使用带本机令牌的 `POST /visual/{runId}/pause|resume`。未启用自动托管也可独立暂停视觉测试。

失败现场经本人核验并重新授权后，可调用带本机令牌的 `POST /visual/{runId}/targets/{targetId}/reconfirm`，提交原 `proposalId`、`expectedVersion`、完整 `draft` 和 `confirmed=true`；前次为未知结果时还必须明确 `possibleDuplicateAccepted=true`。该操作只在暂停后复核相同 HR 消息轮、没有新增本人回复、草稿为空或与批准原文相同，才创建新提案和新步骤，仍保持暂停。V31 追加旧/新提案关联，旧未知和失败记录原样保留，重复确认请求失效；普通“恢复”不会重发未知步骤。部分步骤已经成功时禁止通过这个入口重新发文字。

若消息实际已送达但回执读取失败，可在工作台点击“只读核验发送回执”（带本机令牌的 `POST /visual/{runId}/targets/{targetId}/reconcile`）。它只打开并读取原会话，使用该未知步骤持久保存的完整发送前消息比对新增本人消息，不输入、不提交、不重新排队。成功才追加 V32 审计、保留原未知证据并更新结果；失败保留未知及原发送前截图。缺少完整原证据时不能补认成功。已知完整 HR 轮可作为滚动边界恢复依据，但当前 HR 轮的原文、类型、时间必须全部匹配。

若文字已核验、原生简历仍未提交，运行保持暂停和“部分完成”；恢复后只执行原授权中剩余的未提交步骤，不重发文字。提交授权前会持久保存完整聊天快照，管道中断和进程重启也保留该检查点，供只读核验使用；检查点本身不能证明已发送。

## 发送约束和证据

### 单轮检查其他 HR（V34）

暂停后可选择“处理已发现的全部会话”，依次处理本轮已收集名单，保留原分页与覆盖未完成记录，后续暂停/恢复不重新枚举。接口 `POST /visual/batches/{id}/process` 提交 `protocol`、`replyMode` 和 `directRepliesConfirmed`。默认仍为 REVIEW；只有明确选择 AUTO 且确认后，本批次普通文字才经生成与独立审核直接进入视觉发送队列，不发送 QQ 确认卡。不会启用长期托管或改变其他批次授权。

V35 增量保存本轮模式、确认时间、资料摘要及已审核标记。旧批次仍为 REVIEW。仅审核结果 TEXT 可直发；拒绝机会、敏感事项、未知事实和审核失败留待本人处理并继续其他会话。原待确认卡会重新读正文并独立审核，旧未知、已发送和人工草稿不自动重试。提交前复核全局档案与会话补充事实摘要。发送未知时冻结该会话、保存失败现场，只读重新锁定未知身份后继续其他联系人；人工操作、焦点变化和平台验证仍暂停整轮。只处理完已发现名单不能冒充列表覆盖完整。

`POST /api/hr-assistant/visual/batches` 使用本机操作令牌，参数为 `profileId`、`protocol`、幂等 `requestKey`、`accountName`、`accountBindingConfirmed` 和 `resumeSharingConfirmed`。仅检查最近 30 天，排除原三会话测试目标；不修改持续值守/自动文字授权。`POST /visual/batches/{id}/pause|resume` 控制本轮，恢复不再取得新开页额度。重复启动键返回原批次，内容不同则拒绝。

批次依次执行首次准备、旧未知身份只读核验、逐屏枚举、逐项读取。只有首次准备可以在既有 Chrome 登录窗口中打开一次固定聊天 URL；该额度在调用执行器前持久化。后续操作仅复用现有标签，窗口关闭、焦点变化或平台验证时暂停，不刷新、重开或重新输入网址。读取用 Windows UIA 与 OCR，不依赖 Codex 浏览器工具；工具连接错误不能作为 BOSS 加载状态。

首次等待列表和账号最多 30 秒；列表可见但未选择联系人明确显示为独立阶段。联系人通过原生搜索定位，点击后等 3 秒，总计最多 20 秒核对正文。读取错误会清空前一次稳定快照，岗位变化也不能复用稳定结果。协议支持 progress 帧，后端总超时不随进度续期；状态接口保留最近成功观察的原时间，并单独显示当前错误。

逐屏枚举保留重叠联系人，持久化游标与候选。缺少重叠标记覆盖有缺口；只有原生末尾标记与滚动到底同时成立并稳定、且两次完整枚举的身份顺序和预览一致才能确认覆盖完成。两次枚举不一致则明示可能有联系人重排，不自动反复重扫。三次无进展或每遍 200 页后本轮停止发现并保留覆盖不完整。身份截断、日期不明及正文失败的联系人不计入已核验正文数。中断后明确恢复，从头重新枚举以验证覆盖，已有候选去重；处理阶段从未处理项继续，先重新核验旧未知身份锚点。

旧未知会话只有当前完整身份、岗位和原 HR 来源轮次仍匹配，才记录本批次只读身份锚点；未知状态本身保持冻结。关联已有或新视觉身份都必须覆盖档案下全部未知会话锚点，新增未知或无法核验时仍拒绝；不把视觉身份伪造成平台 UID。无法安全关联的联系人保存待核验通知，不生成可执行确认码。

REVIEW 模式的普通建议使用现有模型生成和审核，进入 QQ 逐条确认并保存通知状态；等待确认不阻塞继续扫描。AUTO 模式依照本轮显式授权和审核结果直接发送。简历单独生成原生步骤，提交前再检查本批次未暂停和原请求未变化。每个会话边界优先处理已排队步骤；扫描结束后停止发现，QQ 后续确认仅执行对应已有卡片。`FINISHED` 仅代表扫描完成，必须分别查看发送回执；`INCOMPLETE` 明示覆盖或读取未完成。服务重启将活动批次暂停，并保留发送未知保护。

V34 仅追加批次、候选、页面观察表和一次开页标记。升级默认不启动；回滚保留 V34 与新消息、步骤结果，使用含迁移兼容的程序回滚，不覆盖生产数据库。

原生列表没有 UIA ScrollPattern 时，在每次新观察核验的联系人行区域发送鼠标滚轮。首次先验证滚轮确实改变列表，再有界回到顶部并连续核对文字与位置；滚轮不生效时不能宣称到顶。后续小步下滚并保留跨页重叠，只有明确末尾文字及追加下滚无变化才确认底部。顶部固定筛选栏后方的裁剪行不参与联系人识别，防止把“未读”等控件内容合成联系人。滚动模式随游标保存；不会使用 Home/PageDown 或地址栏导航。

### HR 索要简历时直接发送

批次状态按 `textSentConfirmed`、`resumeSentConfirmed` 分别统计本批次实际确认的文字步骤和原生简历步骤；即使随后步骤未知，也保留已经确认的动作数。原 `sent` 字段仍表示当前尝试全部步骤确认的联系人数。`unknownSteps` 统计该批次保留的未知步骤，显式重确认后的新尝试成功也不隐藏旧未知记录。`statusCounts` 与未处理、待资料或审核、读取失败、未知等数量只统计本批次候选联系人，旧未知身份锚点不混入本轮。`noReply` 对应已跳过项，包含已回复、无需回复、超出 30 天等情形，应结合逐项原因查看。已发现数和已核验数都不代表覆盖完整。

工作台提供独立的自动简历授权。开启后普通文字仍保持 QQ 逐条确认；每分钟读取当前 Chrome 已加载联系人列表，仅对新出现或预览变化的联系人核对正文。未加载的历史列表不算已检查，不自动刷新页面。后台巡检、自动简历及只读回执核验只使用已有 BOSS 标签；标签丢失时停止，不自动新开或重新导航。姓名、公司、岗位、账号和完整请求须核验；新视觉联系人使用 `boss_visual / visual:<稳定本地标识>`，不冒充平台 UID。已知联系人的岗位变化时停止，不创建新身份绕过去重。

明确的索要请求才生成单独的 `RESUME_NATIVE` 步骤。优先点击该 HR 简历请求卡片内的“同意”，无请求卡片时使用工具栏“发简历”；绝不点击电话或微信请求的同意，也不附带文字。拒绝、撤回、已发简历、已有未知结果、非空人工草稿会停止该会话。每份请求按会话和来源去重，普通扫描和服务重启不重发。停用或修改规则版本后，原排队任务不能沿用旧授权提交。

V33 新增规则、联系人巡检进度、请求与执行记录的关联表。默认关闭；升级不会继承旧 shareResume 授权。发生人工操作、焦点变化、锁屏或网站验证时规则暂停，原因在工作台显示。规则重启仍保留，但中断发送的步骤继续保持未知，禁止自动重试。

- 会话均先只读核对，再领取发送步骤。联系人搜索只点击姓名、公司和岗位经过稳定核验的搜索浮层项，不点击浮层后面的列表。高亮姓名通过该结果项的完整可访问名称核验，岗位须与随后正文一致。当前选中行不在列表视口时，正文标题必须独立显示完整姓名与公司；无法核验时停止。核对完整待回复消息轮后才关联原平台会话，不生成假的平台 ID。
- 切换后等待 3 秒，有界等待稳定正文最多 20 秒。可见且完整的上一条本人消息界定本轮上下文；被截断的待回复消息、无法辨别的媒体、空白正文会阻塞。平台竞争分析推广卡不作为 HR 发言；简历请求卡中的“同意/拒绝”控件不作为消息原文。
- 首次聊天缺少本人历史消息时，完整历史标记必须位于已核验的消息列表内且不属于聊天消息。HR 正文或工具栏即使出现“没有更多消息”等相同文字，也不能作为历史已完整读取的证据；无法核验标记归属时保持上下文未核验。
- 精确完整的 UIA 文本用于事实与发送回执比对。OCR只辅助确认正文可见，支持高 DPI 下的气泡范围复核；短消息须完整识别，长消息需高字符覆盖，不能用匹配前几个字替代发送回执。
- 私有 stdin/stdout 子进程协议分为准备、后端再次授权、单次提交、回执。输入已有未知草稿时停止；仅人工复核后新建的尝试可以沿用完全匹配的已批准草稿。文字换行使用 Ctrl+Enter；提交时核验编辑器没有被遮挡、焦点仍在编辑器内，再发送一次原生 Enter，避免旧助手浮窗覆盖鼠标发送按钮。
- 原生简历不上传本地文件。只有一个可核验的简历文件时才能确认选择弹窗，确认前再次比对聊天。多个文件或名称无法读取时交本人选择，不猜测。
- 每个步骤至少间隔 5 秒，完成时间持久化。提交后等待匹配新增本人消息最多 15 秒；列表自动置顶的短暂选中状态只允许继续只读核验，不重复提交。“送达”等气泡状态按状态控件范围排除，不混入正文。点击成功、输入框清空、旧消息均不算成功。未知状态不自动重试。文字已成功而简历未成功时保留两步结果。
- 截图只保存本次正文范围，使用当前 Windows 用户的 DPAPI 加密，位于 `APP_DATA_DIR/hr-visual-evidence`；准备阶段即保存发送前截图，失败也保留已核验的前文。只有观察到真实回执才保存发送后截图；步骤证据在数据库中加密保存。不要提交截图、运行记录、密钥或真实聊天数据。
- 过期且已停止的运行按现有资料保留天数清理正文副本及截图；步骤状态、时间和未知结果仍保留，不恢复为待发任务。

## 测试、部署和回滚

单轮名单较多时，可暂停列表扫描，在“本轮逐项结果”中优先处理一名已发现的联系人。该操作沿用本轮授权、重新核验旧未知会话身份，只对明确索要简历的消息排队原生简历；普通文字仍生成 QQ 待确认卡。重复点击不重复排队。优先项处理后重新枚举名单以核验发送导致的排序变化，保留已处理结果；不会重新打开或刷新标签。接口为 `POST /api/hr-assistant/visual/batches/{id}/items/{itemId}/prioritize`，须本机操作令牌。没有数据库结构变化。

优先核验前先让联系人列表回到已验证的顶部，避免旧未知会话滚出视口后缺少公司信息。较长列表仍有上滚进展时保存 `seekingTop` 检查点，下一次有界操作继续；没有滚动响应或边界核验失败时仍暂停。返回顶部前不把中间视口当作列表起点或完成覆盖。前置读取失败且从未关联发送运行的联系人可通过 `/recheck` 显式重新核验；已有发送运行、已发送和未知结果不允许由此重新排队。

```powershell
hr-visual/.venv/Scripts/python.exe -m unittest discover -s hr-visual/tests -v
./gradlew.bat test bootJar
# front 目录：pnpm typecheck；pnpm lint；pnpm test；pnpm build:prod
# chrome-extension/tests 下的 node:test 兼容测试
```

部署沿用原 RunDock Backend、6866 端口和运行目录。先使用 SQLite Online Backup 备份实际数据库并备份配置、密钥；在原运行目录更新已合并版本，安装独立环境，停止再启动同一服务记录。V30 只增列和新表，保留原消息/发送记录。升级不会自动创建视觉 run 或开启自动值班。
