# 1.3 多平台采集与分析增强版

本文记录 1.3 版本阶段、已完成能力、运行方式、风险边界和后续计划。文件名沿用早期 `1.0自动投简历脚本.md`，用于兼容现有文档链接。

## 阶段定位

阶段名称：`1.3 多平台采集与分析增强版`

阶段目标：在本机完成从配置检查、岗位搜索、岗位采集、AI 匹配、待确认列表、人工确认、用户确认后投递到结果统计的闭环。项目不是云端 SaaS，也不是无人值守批量投递系统；当前设计更强调本地运行、可观察、可暂停、可人工确认。

## 1.3 主流程

```text
打开前端 GUI
  ↓
通过工作台检查配置完整度
  ↓
填写环境配置、AI 配置和平台配置
  ↓
登录目标招聘平台
  ↓
启动平台扫描
  ↓
采集岗位并写入后端
  ↓
AI 分析岗位匹配度
  ↓
命中岗位进入待确认
  ↓
用户在分析页确认投递
  ↓
Chrome Bridge 或 Playwright 执行投递
  ↓
投递状态回写 SQLite
  ↓
分析页查看统计和列表
```

## Chrome Bridge 路线

Chrome Bridge 位于：

```text
chrome-extension/
```

使用方式：

1. 打开 `chrome://extensions/`。
2. 开启开发者模式。
3. 选择“加载已解压的扩展程序”。
4. 选择项目目录下的 `chrome-extension/`。
5. 在 Chrome 中登录 Boss 或智联。
6. 回到前端平台页启动 Chrome 扫描。

扩展提供的能力：

- 前端页面与扩展通信。
- 打开或复用 Boss、智联平台标签页。
- 在平台页面采集岗位列表和详情。
- 将采集结果提交后端 AI 分析。
- 在分析页确认后执行单个或批量投递。
- 将投递成功或失败写回后端。

## 数据状态说明

投递数据会在本地 SQLite 中维护，常见状态包括：

| 状态 | 含义 |
| --- | --- |
| `未投递` | 已采集但尚未通过 AI 或人工确认 |
| `待确认` | AI 判断适合，等待用户确认是否投递 |
| `已投递` | 已通过 Chrome 或 worker 执行投递并写回成功 |
| `投递失败` | 投递按钮、页面状态或网络异常导致失败 |
| `已跳过` | 用户在待确认阶段手动跳过 |
| `已过滤` / `AI不匹配` / `AI分析失败` | 不进入投递确认的岗位 |

## 文件整理结果

本阶段整理后，Git 只保存源码、配置模板、Docker 文件、Chrome 扩展、前端锁文件和文档。以下内容不进入提交：

- `.env` 和真实 API Key。
- `db/`、`*.db` 本地数据库。
- `logs/`、`output/`、`data/`、`target/`、`build/`。
- `front/node_modules/`、`front/.next/`、`.pnpm-store/`。
- Cookie、简历图片和其他个人隐私文件。

## 已知限制

- 招聘平台页面结构会变化，定位器和内容脚本需要持续维护。
- Boss 和智联网页端可能出现安全验证、登录态失效、按钮文案变化。
- AI 分析结果只能作为辅助判断，投递前仍建议人工确认。
- Chrome Bridge 需要用户在本机 Chrome 中安装扩展并保持登录。
- 本项目建议本地运行，不建议部署到服务器批量执行。

## 下一阶段建议

- 增加更多端到端实测记录，按平台记录账号状态、采集数量、待确认数量和失败原因。

- 将 Boss 和智联的扫描配置、AI 阈值、待确认数量限制做成更明确的 UI 控制。
- 扩展关键 service 单元测试，覆盖更多 AI 分析结果入库和投递状态回写场景。
