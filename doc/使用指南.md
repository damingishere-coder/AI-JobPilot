# 使用指南

本文面向希望直接运行投递牛马的使用者，覆盖环境准备、启动方式、网页端配置、平台使用和常见问题。

当前项目阶段：`1.3 多平台采集与分析增强版`。当前推荐工作流是配置检查 → 扫描岗位 → AI 分析 → 待确认 → 用户确认后投递 → 状态回写 → 分析统计。

## 运行前准备

### 基础环境

- JDK 21
- Node.js 20.19 或更高版本
- pnpm
- IntelliJ IDEA 或其他 Java IDE
- 本机可正常访问 Boss 直聘、猎聘、51job、智联招聘等目标网站
- Chrome 浏览器，Boss/智联的 Chrome Bridge 路线需要加载本地扩展

### 网络与账号

- 建议关闭境外代理后再访问国内招聘平台。
- 不建议将项目部署到服务器运行，招聘网站可能识别服务器 IP 并拒绝返回正常数据。
- 使用自动化投递前，请先理解平台规则、账号风控和每日投递上限。

## 启动项目

### 启动后端

在项目根目录运行：

```bash
./gradlew bootRun
```

如果 macOS 或 Linux 提示 `permission denied: ./gradlew`，先执行：

```bash
chmod +x gradlew
```

也可以临时使用：

```bash
sh gradlew bootRun
```

后端默认监听：

```text
http://localhost:8888
```

后端配置文件：

```text
src/main/resources/application.yaml
```

### 启动前端

在 `front` 目录运行：

```bash
pnpm install
pnpm dev
```

前端默认监听：

```text
http://localhost:6866
```

前端端口和后端地址配置在：

```text
front/server.config.js
```

### 生产构建

如果需要构建前端静态产物：

```bash
cd front
pnpm build:prod
```

构建脚本会执行 Next.js 静态导出，并把 `front/out` 复制到 `src/main/resources/dist`。后端启动时会检测 `src/main/resources/dist`，存在静态资源时可通过后端地址访问管理页面。

## 网页端配置流程

1. 打开 `http://localhost:6866`。
2. 进入环境配置页面，填写企业微信机器人地址等全局配置。
3. 进入 AI 配置页面，填写模型服务地址、API Key 和模型名称。
4. 进入具体招聘平台页面，配置岗位、城市、薪资、投递页数和筛选条件。
5. 点击登录或扫码，完成目标平台登录。
6. 保存 Cookie。
7. 点击开始运行，观察页面中的实时进度和运行日志。
8. 投递结束后到岗位分析页面查看统计结果。

## Chrome Bridge 使用流程

Boss 和智联在 1.3 版本继续使用并增强 Chrome Bridge 路线。它会复用你本机 Chrome 中已登录的平台标签页，支持扫描断点恢复、异常页识别和失败降级，适合绕开后端 Playwright 浏览器登录态不稳定的问题。

### 安装扩展

1. 打开 Chrome 地址 `chrome://extensions/`。
2. 开启开发者模式。
3. 点击“加载已解压的扩展程序”。
4. 选择项目中的 `chrome-extension/` 目录。
5. 回到前端页面，确认扩展连接状态正常。

### 扫描与确认投递

1. 在 Chrome 中登录 Boss 或智联。
2. 回到投递牛马前端平台页，保存平台配置和 AI 配置。
3. 点击 Chrome 扫描入口。
4. 扩展会打开或复用平台标签页，采集岗位列表和详情。
5. 后端收到岗位后执行 AI 分析，命中岗位会进入“待确认”。
6. 到对应平台的岗位分析页，筛选 `待确认`。
7. 点击单个 Chrome 投递，或批量投递当前筛选的待确认岗位。
8. 投递完成后，状态会写回为 `已投递` 或 `投递失败`。

实际投递前请看清确认弹窗。建议每次先少量投递，确认账号没有触发安全验证后再继续。

## AI 配置

AI 配置主要用于 Boss 直聘岗位匹配和打招呼语生成。常见字段包括：

| 字段 | 说明 |
| --- | --- |
| `HOOK_URL` | 企业微信机器人 webhook，用于推送运行消息 |
| `BASE_URL` | 模型服务地址，可使用直连或中转地址 |
| `API_KEY` | 模型服务 API Key |
| `MODEL` | 模型名称 |

示例：

```text
HOOK_URL=https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=your_key_here
BASE_URL=https://api.openai.com
API_KEY=sk-xxx
MODEL=gpt-5-nano
```

请妥善保管 API Key，不要提交到公开仓库。

岗位匹配分数线在“Boss投递分析”页面的“岗位数据”区域设置。普通公司分数线默认75，优先公司分数线默认65。如果希望60分及以上的岗位进入待确认，可以把普通公司分数线设置为60；若希望所有公司都使用同一标准，同时把优先公司分数线设置为60。分数达到阈值后不会直接投递，仍需到岗位分析页确认。

## 平台说明

### Boss 直聘

- 支持岗位搜索、筛选、AI 打招呼语、黑名单和投递进度推送。
- 支持 Chrome Bridge 扫描、AI 分析、待确认列表和确认投递。
- 网页端稳定性弱于手机端，不建议完全依赖程序投递。
- 如果出现掉线或风控迹象，建议当天停止继续投递。
- 如需发送图片简历，请将简历图片放在资源目录并开启相关配置。注意不要把个人简历图片提交到仓库。

### 猎聘

- 支持扫码登录、岗位搜索、筛选和投递。
- 通常需要在猎聘 App 里配置默认打招呼语。
- 原项目说明中提到猎聘更适合批量打招呼，但主动发消息可能存在上限。

### 51job

- 支持配置、登录、投递、统计和结果列表。
- 平台岗位质量和投递上限可能变化，建议小批量运行并观察结果。

### 智联招聘

- 支持配置、登录、投递和统计。
- 支持 Chrome Bridge 扫描、AI 分析、待确认列表和确认投递。
- 当前项目说明中标注智联链路不稳定，使用前建议先小范围测试。
- 需要确认默认简历设置，否则可能投递失败。

## 投递状态说明

| 状态 | 说明 |
| --- | --- |
| `未投递` | 岗位已入库，尚未由用户确认投递 |
| `待确认` | AI 判断适合，等待用户在分析页确认 |
| `已投递` | 已执行投递并写回成功 |
| `投递失败` | 页面按钮、登录态、安全验证或网络导致失败 |
| `已跳过` | 用户手动跳过 |
| `已过滤` / `AI不匹配` / `AI分析失败` | 不建议投递或分析不可用 |

## 数据与隐私

本项目会在本地保存运行数据和配置：

```text
db/getjobs.db
target/logs/get-jobs.log
```

请注意：

- `db/` 和 `*.db` 已在 `.gitignore` 中忽略。
- `.pnpm-store/`、`front/node_modules/`、`front/.next/` 等依赖缓存和构建产物已忽略。
- Cookie、API Key、简历图片和个人数据不要提交到公开仓库。
- 如果需要分享项目目录，建议先删除数据库、日志、Cookie 和个人简历文件。

## 常见问题

### 后端启动后打不开页面

后端只负责 API 和可选静态资源服务。开发时需要单独启动前端：

```bash
cd front
pnpm dev
```

然后访问 `http://localhost:6866`。

### 前端请求接口失败

确认后端已经启动，并能访问：

```text
http://localhost:8888/api/health
```

同时确认 `front/server.config.js` 中 `api.baseUrl` 保持为空，`api.proxyTarget` 指向 `http://localhost:8888`。这样浏览器侧只请求同源 `/api`，由 Next.js 开发服务代理到后端。

### Playwright 初始化失败

确认网络可以下载或访问 Playwright 依赖浏览器。项目会使用 Playwright 执行浏览器自动化，不再依赖 chromedriver。

### 平台扫码后仍提示未登录

可能是 Cookie 未保存、平台会话过期或风控导致。建议重新登录并保存 Cookie，再小批量测试。

### 运行时页面加载很慢

建议关闭代理，确认本机网络可以直接访问目标招聘网站。
