# 架构说明

Get Jobs 当前采用本地单机架构：前端负责图形化配置和结果展示，后端负责 API、数据库和任务调度，worker 负责 Playwright 浏览器自动化。

## 总体结构

```text
┌──────────────────────────────┐
│ 前端 front                    │
│ Next.js / React / Tailwind    │
│ 端口 6866                     │
└───────────────┬──────────────┘
                │ HTTP / SSE
                ▼
┌──────────────────────────────┐
│ 后端 application              │
│ Spring Boot / Controller      │
│ Service / Mapper / SQLite     │
│ 端口 8888                     │
└───────────────┬──────────────┘
                │ Java 调用
                ▼
┌──────────────────────────────┐
│ 执行层 worker                 │
│ Playwright / 平台执行逻辑      │
│ Boss / Liepin / 51job / Zhilian│
└──────────────────────────────┘
```

## 前端层

位置：

```text
front/
```

主要职责：

- 平台配置表单。
- 登录、保存 Cookie、启动和停止任务。
- 通过 SSE 接收运行进度。
- 展示岗位统计和投递结果列表。

主要页面：

| 路径 | 说明 |
| --- | --- |
| `/` | 首页/工作台 |
| `/env-config` | 环境配置 |
| `/ai-config` | AI 配置 |
| `/boss` | Boss 直聘配置和运行 |
| `/boss/analysis` | Boss 直聘岗位分析 |
| `/liepin` | 猎聘配置和运行 |
| `/liepin/analysis` | 猎聘岗位分析 |
| `/51job` | 51job 配置和运行 |
| `/51job/analysis` | 51job 岗位分析 |
| `/zhilian` | 智联招聘配置和运行 |
| `/zhilian/analysis` | 智联招聘岗位分析 |

## 后端应用层

位置：

```text
src/main/java/com/getjobs/application
```

主要职责：

- 暴露 REST 和 SSE 接口。
- 读写 SQLite 数据库。
- 管理平台配置、AI 配置、Cookie 和黑名单。
- 调用 worker 服务启动或停止自动化任务。
- 将执行进度推送给前端。

关键目录：

| 目录 | 说明 |
| --- | --- |
| `controller` | API 和 SSE 接口 |
| `service` | 业务服务 |
| `mapper` | MyBatis-Plus 数据访问 |
| `entity` | 数据库实体 |
| `config` | CORS、静态资源、异步执行、启动行为 |
| `init` | 初始化数据和 Cookie 种子逻辑 |

## Worker 执行层

位置：

```text
src/main/java/com/getjobs/worker
```

主要职责：

- 初始化 Playwright 浏览器。
- 打开招聘网站并完成登录态复用。
- 根据配置搜索岗位。
- 执行岗位过滤、黑名单判断和薪资判断。
- 自动发送打招呼语或投递简历。
- 回传执行进度和投递结果。

平台目录：

| 目录 | 说明 |
| --- | --- |
| `boss` | Boss 直聘 |
| `liepin` | 猎聘 |
| `job51` | 前程无忧 51job |
| `zhilian` | 智联招聘 |

## 数据层

数据库文件：

```text
db/getjobs.db
```

连接配置：

```yaml
spring:
  datasource:
    url: jdbc:sqlite:./db/getjobs.db
```

典型数据：

- 全局配置。
- AI 配置。
- 平台配置。
- Cookie 和登录状态。
- 平台选项数据。
- 投递结果数据。
- 黑名单数据。

## 运行流程

```text
用户在前端点击开始
  ↓
前端调用后端平台 start 接口
  ↓
后端读取平台配置和 Cookie
  ↓
后端调用对应 worker service
  ↓
worker 使用 Playwright 操作目标网站
  ↓
执行过程中生成进度消息
  ↓
后端通过 SSE 推送给前端
  ↓
投递结果写入 SQLite
  ↓
前端分析页读取统计和列表数据
```

## SSE 进度推送

不同平台使用各自的进度流接口，例如：

```text
GET /api/boss/stream
GET /api/51job/stream
```

前端通过 `EventSource` 建立连接。`front/lib/sse.ts` 封装了自动重连和页面卸载清理逻辑。

## 启动行为

后端启动后，`StartupRunner` 会：

1. 检查前端 `6866` 端口是否已有服务。
2. 如果有，尝试打开前端管理页面。
3. 如果没有，检查 `src/main/resources/dist` 是否存在静态资源。
4. 如果存在，尝试打开后端页面。
5. 随后初始化 Playwright。

## 设计约束

- 当前架构以本地单用户使用为主。
- Cookie、数据库和日志都保存在本机。
- 自动化行为依赖招聘平台页面结构，平台改版后可能需要更新定位器。
- 项目不建议服务器部署，招聘网站可能对服务器 IP 有访问限制。
