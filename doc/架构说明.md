# 架构说明

投递牛马当前采用本地单机架构：前端负责图形化配置和结果展示，后端负责 API、数据库和任务调度，worker 负责 Playwright 浏览器自动化，Chrome Bridge 扩展负责复用用户已登录的 Chrome 标签页完成 Boss/智联“扫描岗位 → AI 分析 → 待确认 → 用户确认后投递”流程。

当前阶段：`1.3 多平台采集与分析增强版`。

## 总体结构

```text
┌──────────────────────────────┐
│ 前端 front                    │
│ Next.js / React / Tailwind    │
│ 端口 6866                     │
└───────────────┬──────────────┘
                │ HTTP / SSE / window.postMessage
                ▼
┌──────────────────────────────┐
│ 后端 application              │
│ Spring Boot / Controller      │
│ Service / Mapper / SQLite     │
│ 端口 8888                     │
└───────┬───────────────────────┘
        │ Java 调用
        │
        ▼
┌──────────────────────────────┐
│ 执行层 worker                 │
│ Playwright / 平台执行逻辑      │
│ Boss / Liepin / 51job / Zhilian│
└──────────────────────────────┘

前端也可以通过 Chrome Bridge 调用用户 Chrome：

┌──────────────────────────────┐
│ Chrome Bridge 扩展            │
│ chrome-extension/             │
│ Boss / Zhilian content script │
└───────────────┬──────────────┘
                │ fetch 后端 API
                ▼
┌──────────────────────────────┐
│ 后端 application / SQLite      │
│ AI 分析 / 待确认 / 状态回写     │
└──────────────────────────────┘
```

## 前端层

位置：

```text
front/
```

主要职责：

- 平台配置表单。
- 登录、保存 Cookie、启动和停止任务。
- 通过 SSE 接收运行进度。
- 展示岗位统计和投递结果列表。
- 通过 `front/lib/chromeBridge.ts` 与 Chrome Bridge 扩展通信。
- 在 Boss/智联分析页生成单个或批量确认投递任务。

主要页面：

| 路径 | 说明 |
| --- | --- |
| `/` | 首页/工作台 |
| `/env-config` | 环境配置 |
| `/ai-config` | AI 配置 |
| `/boss` | Boss 直聘配置和运行 |
| `/boss/analysis` | Boss 直聘岗位分析 |
| `/liepin` | 猎聘配置和运行 |
| `/liepin/analysis` | 猎聘岗位分析 |
| `/51job` | 51job 配置和运行 |
| `/51job/analysis` | 51job 岗位分析 |
| `/zhilian` | 智联招聘配置和运行 |
| `/zhilian/analysis` | 智联招聘岗位分析 |

## Chrome Bridge 扩展层

位置：

```text
chrome-extension/
```

主要职责：

- 在前端本地页面注入 `page-bridge.js`，接收 `window.postMessage`。
- 在 Boss、智联页面注入 content script。
- 复用或打开用户已登录的招聘平台标签页。
- 扫描岗位列表、打开岗位详情并提取结构化数据。
- 调用后端 `/api/boss/chrome/jobs`、`/api/zhilian/chrome/jobs` 提交采集结果。
- 接收前端确认投递任务，在平台页面点击投递按钮。
- 调用后端投递结果接口回写 `已投递` 或 `投递失败`。

关键文件：

| 文件 | 说明 |
| --- | --- |
| `manifest.json` | Chrome 扩展声明和域名权限 |
| `background.js` | 扩展后台调度、标签页查找、投递任务编排 |
| `page-bridge.js` | 前端页面与扩展之间的消息桥 |
| `boss-content.js` | Boss 页面扫描和投递逻辑 |
| `zhilian-content.js` | 智联页面扫描和投递逻辑 |

## 后端应用层

位置：

```text
src/main/java/com/getjobs/application
```

主要职责：

- 暴露 REST 和 SSE 接口。
- 读写 SQLite 数据库。
- 管理平台配置、AI 配置、Cookie 和黑名单。
- 调用 worker 服务启动或停止自动化任务。
- 将执行进度推送给前端。
- 接收 Chrome Bridge 采集结果并执行 AI 分析。
- 生成待确认投递任务并回写投递结果。

关键目录：

| 目录 | 说明 |
| --- | --- |
| `controller` | API 和 SSE 接口 |
| `service` | 业务服务 |
| `mapper` | MyBatis-Plus 数据访问 |
| `entity` | 数据库实体 |
| `config` | CORS、静态资源、异步执行、启动行为 |
| `init` | 初始化数据和 Cookie 种子逻辑 |

## Worker 执行层

位置：

```text
src/main/java/com/getjobs/worker
```

主要职责：

- 初始化 Playwright 浏览器。
- 打开招聘网站并完成登录态复用。
- 根据配置搜索岗位。
- 执行岗位过滤、黑名单判断和薪资判断。
- 在用户确认或平台 worker 流程触发后发送打招呼语或投递简历。
- 回传执行进度和投递结果。

平台目录：

| 目录 | 说明 |
| --- | --- |
| `boss` | Boss 直聘 |
| `liepin` | 猎聘 |
| `job51` | 前程无忧 51job |
| `zhilian` | 智联招聘 |

## 数据层

数据库文件：

```text
db/getjobs.db
```

连接配置：

```yaml
spring:
  datasource:
    url: jdbc:sqlite:./db/getjobs.db
```

典型数据：

- 全局配置。
- AI 配置。
- 平台配置。
- Cookie 和登录状态。
- 平台选项数据。
- 投递结果数据。
- 黑名单数据。

## Profile 档案隔离

Profile 用于隔离不同候选人、简历或求职方向的数据上下文。后端通过当前激活档案的 `profile_id` 读写数据，前端通过 ProfileSwitcher 切换当前档案。

正在按 `profile_id` 隔离的数据包括：

- AI 配置。
- 简历信息。
- 平台配置。
- Boss/智联岗位数据。
- AI 分析结果。

当前 Boss 和智联的统计、列表、清空分析、确认投递和投递结果回写均按当前档案读取或写入；切换档案后，页面只展示当前档案范围内的数据。后续继续扩展时，新增配置表、岗位表或分析表也应带上 `profile_id`，避免不同候选人数据互相混用。

## Playwright 运行流程

Boss/智联推荐使用 Chrome Bridge 确认式流程；保留的 Playwright worker 主要用于既有平台自动化链路，运行前应确认账号状态、平台规则和配置。

```text
用户在前端点击开始
  ↓
前端调用后端平台 start 接口
  ↓
后端读取平台配置和 Cookie
  ↓
后端调用对应 worker service
  ↓
worker 使用 Playwright 操作目标网站
  ↓
执行过程中生成进度消息
  ↓
后端通过 SSE 推送给前端
  ↓
投递结果写入 SQLite
  ↓
前端分析页读取统计和列表数据
```

## Chrome Bridge 运行流程

```text
用户在 Chrome 登录 Boss/智联
  ↓
前端通过 chromeBridge 发送扫描任务
  ↓
Chrome 扩展打开或复用平台标签页
  ↓
content script 采集岗位列表和详情
  ↓
扩展提交到后端 chrome/jobs 接口
  ↓
后端入库并调用 AI 分析
  ↓
命中岗位标记为待确认
  ↓
用户在分析页确认投递
  ↓
扩展在 Chrome 平台页执行投递
  ↓
后端 delivery-result 接口写回投递状态
```

## SSE 进度推送

不同平台使用各自的进度流接口，例如：

```text
GET /api/boss/stream
GET /api/51job/stream
```

前端通过 `EventSource` 建立连接。`front/lib/sse.ts` 封装了自动重连和页面卸载清理逻辑。

## 启动行为

后端启动后，`StartupRunner` 会：

1. 检查前端 `6866` 端口是否已有服务。
2. 如果有，尝试打开前端管理页面。
3. 如果没有，检查 `src/main/resources/dist` 是否存在静态资源。
4. 如果存在，尝试打开后端页面。
5. 随后初始化 Playwright。

## 设计约束

- 当前架构以本地单用户使用为主。
- Cookie、数据库和日志都保存在本机。
- 自动化行为依赖招聘平台页面结构，平台改版后可能需要更新定位器。
- Chrome Bridge 依赖用户本机 Chrome、扩展权限和平台登录态。
- 项目不建议服务器部署，招聘网站可能对服务器 IP 有访问限制。
