# 开发指南

本文面向参与维护或二次开发的开发者，整理本地开发、构建、调试和扩展方式。

当前阶段：`1.3 多平台采集与分析增强版`。后端、前端和 Chrome 扩展版本均对齐为 `1.3.0`。

## 项目结构

```text
.
├── build.gradle.kts
├── chrome-extension
│   ├── background.js        # Chrome 扩展后台调度
│   ├── page-bridge.js       # 前端页面消息桥
│   ├── boss-content.js      # Boss 页面内容脚本
│   ├── zhilian-content.js   # 智联页面内容脚本
│   └── manifest.json
├── src/main/java/com/getjobs
│   ├── GetJobsApplication.java
│   ├── application
│   │   ├── config      # Spring 配置、启动逻辑、静态资源配置
│   │   ├── controller  # REST 和 SSE 接口
│   │   ├── entity      # 数据库实体
│   │   ├── init        # 初始化逻辑
│   │   ├── mapper      # MyBatis-Plus mapper
│   │   └── service     # 应用服务
│   └── worker
│       ├── boss        # Boss 直聘自动化
│       ├── job51       # 51job 自动化
│       ├── liepin      # 猎聘自动化
│       ├── zhilian     # 智联招聘自动化
│       ├── manager     # Playwright 生命周期管理
│       ├── service     # 平台 worker 服务
│       └── utils       # 通用工具
├── src/main/resources
│   ├── application.yaml
│   ├── banner.txt
│   └── images
└── front
    ├── app             # Next.js App Router 页面
    ├── components      # UI 组件
    ├── lib             # 前端工具
    ├── scripts         # 构建复制和历史数据迁移脚本
    └── server.config.js
```

## 后端开发

### 运行

```powershell
.\gradlew.bat bootRun
```

macOS 或 Linux 使用：

```bash
./gradlew bootRun
```

如果提示 `permission denied: ./gradlew`，先执行：

```bash
chmod +x gradlew
```

### 测试

```bash
./gradlew test
```

### 构建

```bash
./gradlew build
```

### 关键配置

后端配置文件为：

```text
src/main/resources/application.yaml
```

当前主要配置：

| 配置 | 默认值 |
| --- | --- |
| `server.port` | `8888` |
| `spring.datasource.url` | `jdbc:sqlite:./db/getjobs.db` |
| `logging.file.name` | `./target/logs/get-jobs.log` |
| `app.openclaw.command` | `openclaw` |
| `app.openclaw.profile` | `openclaw` |
| `app.openclaw.detail-limit` | `5` |

## Chrome Bridge 开发

Chrome 扩展目录：

```text
chrome-extension/
```

开发调试步骤：

1. 打开 Chrome `chrome://extensions/`。
2. 开启开发者模式。
3. 加载项目中的 `chrome-extension/`。
4. 修改扩展代码后，在扩展管理页点击重新加载。
5. 刷新前端页面和招聘平台页面。

前端通信入口：

```text
front/lib/chromeBridge.ts
```

后端接收入口：

```text
POST /api/boss/chrome/jobs
POST /api/zhilian/chrome/jobs
POST /api/boss/jobs/{id}/delivery-result
POST /api/zhilian/jobs/{id}/delivery-result
```

扩展内容脚本通常比 Playwright worker 更容易受页面 DOM 改版影响。调整时优先在浏览器控制台验证选择器，再同步更新文档中的平台状态说明。

## 数据库

项目使用 SQLite：

```text
db/getjobs.db
```

MyBatis-Plus 会根据 mapper 和 entity 访问数据库。数据库文件包含本地配置、Cookie、投递数据、平台选项和统计数据。

注意事项：

- `db/` 和 `*.db` 已被 `.gitignore` 忽略。
- 修改表结构前请备份本地数据库。
- 前端有脚本 `front/scripts/migrate-sort-order.mjs` 用于特定字段迁移。

## 自动化执行层

worker 目录按平台拆分：

| 模块 | 说明 |
| --- | --- |
| `worker/boss` | Boss 直聘页面定位和执行逻辑 |
| `worker/job51` | 51job 页面定位和执行逻辑 |
| `worker/liepin` | 猎聘页面定位和执行逻辑 |
| `worker/zhilian` | 智联招聘页面定位和执行逻辑 |
| `worker/manager` | Playwright 初始化和浏览器生命周期管理 |
| `worker/service` | 平台执行服务，供 application service/controller 调用 |

新增平台时，建议沿用现有模式：

1. 在 `worker/<platform>` 下新增平台配置、定位器和执行类。
2. 在 `worker/service` 下新增平台服务。
3. 在 `application/entity`、`mapper`、`service` 下补齐配置和结果数据访问。
4. 在 `application/controller` 下暴露配置、登录、启动、停止、状态、统计接口。
5. 在 `front/app` 下新增配置页和分析页。
6. 如要支持用户 Chrome 登录态，补充 `chrome-extension` 的 content script 和 background 分发逻辑。
7. 更新 [API 接口](API接口.md)、[架构说明](架构说明.md) 和 [1.3 版本说明](1.0自动投简历脚本.md)。

## 静态资源模式

前端开发时由 `pnpm dev` 提供页面服务。生产构建时，Next.js 静态导出会生成 `front/out`，`pnpm build:prod` 会把它复制到：

```text
src/main/resources/dist
```

后端启动后会检测该目录，如果存在静态资源，启动时会尝试打开后端地址访问管理页面。

## 提交前检查

建议提交前至少执行：

```bash
./gradlew test
cd front && pnpm lint && pnpm build
```

如果只改文档，可检查 Markdown 链接、标题和截图路径是否正确。

提交前还要确认本地依赖缓存没有被纳入 Git：

```bash
git status --short
git ls-files .pnpm-store
```

第二条命令应无输出。
