# 开发指南

本文面向参与维护或二次开发的开发者，整理本地开发、构建、调试和扩展方式。

## 项目结构

```text
.
├── build.gradle.kts
├── src/main/java/com/getjobs
│   ├── GetJobsApplication.java
│   ├── application
│   │   ├── config      # Spring 配置、启动逻辑、静态资源配置
│   │   ├── controller  # REST 和 SSE 接口
│   │   ├── entity      # 数据库实体
│   │   ├── init        # 初始化逻辑
│   │   ├── mapper      # MyBatis-Plus mapper
│   │   └── service     # 应用服务
│   └── worker
│       ├── boss        # Boss 直聘自动化
│       ├── job51       # 51job 自动化
│       ├── liepin      # 猎聘自动化
│       ├── zhilian     # 智联招聘自动化
│       ├── manager     # Playwright 生命周期管理
│       ├── service     # 平台 worker 服务
│       └── utils       # 通用工具
├── src/main/resources
│   ├── application.yaml
│   ├── banner.txt
│   └── images
└── front
    ├── app             # Next.js App Router 页面
    ├── components      # UI 组件
    ├── lib             # 前端工具
    ├── scripts         # 启动、构建和迁移脚本
    └── server.config.js
```

## 后端开发

### 运行

```bash
./gradlew bootRun
```

如果提示 `permission denied: ./gradlew`，先执行：

```bash
chmod +x gradlew
```

或临时使用：

```bash
sh gradlew bootRun
```

### 测试

```bash
./gradlew test
```

### 构建

```bash
./gradlew build
```

### 关键配置

后端配置文件为：

```text
src/main/resources/application.yaml
```

当前主要配置：

| 配置 | 默认值 |
| --- | --- |
| `server.port` | `8888` |
| `spring.datasource.url` | `jdbc:sqlite:./db/getjobs.db` |
| `logging.file.name` | `./target/logs/get-jobs.log` |

## 前端开发

### 安装依赖

```bash
cd front
pnpm install
```

### 运行

```bash
pnpm dev
```

### 构建

```bash
pnpm build
```

### 生产静态构建

```bash
pnpm build:prod
```

### Lint

```bash
pnpm lint
```

## 前后端联调

- 前端端口：`6866`
- 后端端口：`8888`
- 后端健康检查：`GET /api/health`
- 前端 API 地址配置：`front/server.config.js`

开发时通常需要同时运行：

```bash
./gradlew bootRun
```

```bash
cd front
pnpm dev
```

## 数据库

项目使用 SQLite：

```text
db/getjobs.db
```

MyBatis-Plus 会根据 mapper 和 entity 访问数据库。数据库文件包含本地配置、Cookie、投递数据、平台选项和统计数据。

注意事项：

- `db/` 和 `*.db` 已被 `.gitignore` 忽略。
- 修改表结构前请备份本地数据库。
- 前端有脚本 `front/scripts/migrate-sort-order.mjs` 用于特定字段迁移。

## 自动化执行层

worker 目录按平台拆分：

| 模块 | 说明 |
| --- | --- |
| `worker/boss` | Boss 直聘页面定位和执行逻辑 |
| `worker/job51` | 51job 页面定位和执行逻辑 |
| `worker/liepin` | 猎聘页面定位和执行逻辑 |
| `worker/zhilian` | 智联招聘页面定位和执行逻辑 |
| `worker/manager` | Playwright 初始化和浏览器生命周期管理 |
| `worker/service` | 平台执行服务，供 application service/controller 调用 |

新增平台时，建议沿用现有模式：

1. 在 `worker/<platform>` 下新增平台配置、定位器和执行类。
2. 在 `worker/service` 下新增平台服务。
3. 在 `application/entity`、`mapper`、`service` 下补齐配置和结果数据访问。
4. 在 `application/controller` 下暴露配置、登录、启动、停止、状态、统计接口。
5. 在 `front/app` 下新增配置页和分析页。
6. 更新 [API 接口](API接口.md) 和 [架构说明](架构说明.md)。

## 静态资源模式

前端开发时由 `pnpm dev` 提供页面服务。生产构建后，可将前端静态产物放到：

```text
src/main/resources/dist
```

后端启动后会检测该目录，如果存在静态资源，启动时会尝试打开后端地址访问管理页面。

## 提交前检查

建议提交前至少执行：

```bash
./gradlew test
cd front && pnpm lint && pnpm build
```

如果只改文档，可检查 Markdown 链接、标题和截图路径是否正确。
