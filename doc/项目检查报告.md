# 项目工程体检报告

检查时间：2026-06-17

## 项目判断

投递牛马当前是一个 Windows 可运行的本地求职辅助项目，由 Spring Boot 后端、Next.js 前端、Chrome Bridge 扩展、Playwright worker 和 SQLite 数据库组成。

本次体检目标是工程收拢、Windows 自查、文档同步和冗余清理，不新增业务功能，不改变核心投递流程、接口字段或数据库结构。

## 当前项目结构

| 路径 | 说明 |
| --- | --- |
| `src/main/java/com/getjobs/application` | 后端应用层，包含 Controller、Service、Mapper、Entity 和配置 |
| `src/main/java/com/getjobs/worker` | Playwright 自动化执行层 |
| `front` | Next.js 前端 |
| `chrome-extension` | Chrome Bridge 扩展 |
| `src/main/resources/db/migration` | Flyway 数据库迁移脚本 |
| `bin` | Windows 辅助脚本 |
| `doc` | 历史文档和补充说明 |
| `README.md`、`ARCHITECTURE.md`、`TASK_FLOW.md`、`WINDOWS_SETUP.md` | 当前主文档 |

## 启动入口

| 入口 | 用途 |
| --- | --- |
| `start_windows.bat` | Windows 本机推荐启动入口 |
| `start_windows.ps1` | Windows PowerShell 启动脚本 |
| `start_docker.bat` / `start_docker.ps1` | Docker 启动入口 |
| `.\gradlew.bat bootRun` | 手动启动后端 |
| `cd front && pnpm dev` | 手动启动前端 |
| `cd front && pnpm build:prod` | 前端静态构建并复制到后端资源目录 |

## 发现的问题

### P0

- `front/scripts/copy-dist.mjs` 和 `front/start-prod.mjs` 使用了旧的 `dist` 目录名，导致 `pnpm build:prod` 在 Next 构建成功后失败。当前 Next 静态导出目录是 `front/out`。
- `src/main/resources/settings.xml` 是旧 Maven 配置，包含个人路径 `H:\Maven3.6.2\repository`，当前 Gradle 项目不使用。
- 主文档对 Windows、`.env`、生产静态构建和当前流程说明不够统一。

### P1

- `front/scripts` 下存在多份未引用旧启动脚本。
- `src/main/resources/xpathHelper.crx` 和 `src/main/resources/images/*.png` 未发现源码或文档引用。
- `.gitignore` 对 Python 缓存、SQLite 变体、临时上传文件和更多前端缓存覆盖不完整。
- `doc` 目录里部分历史文档仍提到 Maven、拉勾、旧构建目录等内容，容易被误读。

### P2

- 平台适配层 `application/platform` 目前是预留抽象，尚未接入统一 Controller。
- 前端 lint 仍有 warning，主要是未使用变量和 React Hook 依赖提示，不阻断构建。
- SaaS 化前还需要做账号、租户、敏感信息加密和任务队列化。

## 本次整理动作

- 修复前端静态构建和静态启动脚本，统一使用 `front/out`。
- 删除确认无引用的旧脚本、旧 Maven 配置和未引用资源。
- 补充 `.gitignore`，避免提交本地数据库、日志、缓存、上传文件和虚拟环境。
- 重写根目录主文档，新增 `TASK_FLOW.md` 和 `WINDOWS_SETUP.md`。
- 更新文档索引，标明历史文档仅供参考。
- 补充轻量自检测试，覆盖启动入口、静态构建目录和 AI JSON 解析等基础风险点。

## 安全结论

- 未发现已提交的真实 API Key、token、Cookie、数据库文件或浏览器缓存。
- `.env.example` 只保留空值和示例路径。
- 本地 `db`、`logs`、`chrome-profile`、`front/node_modules`、`front/out`、`front/.next` 都应继续保持忽略状态。

## Windows 结论

当前 Windows 主路径是合理的：

- `start_windows.bat` 适合新手双击启动。
- Java、Node.js、pnpm 和前端依赖都有中文检查提示。
- 后端默认 `8888`，前端默认 `6866`。
- 路径和日志目录由脚本准备，中文路径通过 UTF-8 设置和已有测试覆盖。

主要注意点：

- 第一次启动前需要 `cd front && pnpm install`。
- Chrome Bridge 需要手动加载 `chrome-extension`。
- `.env` 不是 Windows 本机启动的必填项。
