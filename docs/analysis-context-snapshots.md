# P1.1 不可变简历与分析输入

## 业务行为

新 Chrome 持久任务在入队事务内固定简历版本、智联技能介绍、公司优先标记、阈值、作品集配置、规则版本及 Provider 身份。不同上下文不合批；岗位输入继续保存在原 request_json。后续编辑不改变已有任务输入。

输入相同的历史已完成任务继续复用，不因引入快照而重新计费。同一岗位存在 UNKNOWN 时，即使修改简历或 Provider 参数也不创建新任务；必须先按原入口显式确认/对账。

简历编辑页仍保存当前资料；相同内容在同一档案只形成一个版本。新增版本内容使用现有 AES-GCM 加密能力，独立 AAD 绑定档案和指纹。分析上下文也加密保存；不复制 API Key、Cookie 或招聘平台简历内容。分析用版本不代表实际发送版本。

Provider 调用前检查入队时的路由参数指纹（仅非秘密参数）；变更后停止调用，要求显式重新提交。实际单次请求使用检查过的同一份配置，避免检查后又读取新配置。认证方式、模型选择和已有重试预算不变。更换 API Key 不修改输入事实；Key 不进入快照。

分析详情展示版本、模型、规则与分析时阈值。原分析读模型仍兼容；Legacy 同步分析与历史结果没有完整快照时明确显示“历史上下文不完整”。不能把当前简历回填成旧任务的输入。旧 PENDING 缺快照时在执行前失败，用户可重新提交新分析；旧 UNKNOWN 继续受原确认门禁保护。

## 数据与迁移

V22 只追加：resume_version（profile + 内容指纹去重，UPDATE 触发器禁止改写）、job_analysis_task.context_key、job_ai_analysis.resume_version_id / analysis_context 和批次索引。

不修改 V1–V21，不回填历史简历、不重算岗位、不创建投递。Profile 删除预览和既有显式删除流程纳入版本记录；普通清空分析不删除版本。

部署前排空正常队列并停原服务，制作 SQLite 一致性备份；空库/旧构造库/备份副本执行 Flyway，检查完整性和原表行数。密钥沿用原 HR 加密密钥，恢复时数据库与正确密钥必须配套；不得输出密钥或密文正文。

## 验证

自动化覆盖：排队后改简历/介绍/阈值仍读取原输入、实际 Prompt 使用冻结简历、不同版本不合批、版本不可 UPDATE、同内容幂等、密文不泄露虚构敏感标记、上下文篡改拒绝、历史缺失停止、Provider 改变零 CLI 调用，及现有 UNKNOWN/租约/迁移/档案隔离回归。

手工验收可使用隔离环境的虚构资料与 Mock Provider：任务入队后修改资料，分析详情应显示原版本。正式环境仅核对版本和旧页面兼容，不能为验收自动调用收费 AI。

## 回退与限制

保留新表、新列与已形成事实；不能恢复旧数据库覆盖新数据。旧二进制不能安全执行含新字段的任务，也无法保存后续简历版本；存在新任务时暂停分析并前滚修复，禁止恢复旧消费者写入。

规则版本是显式常量；未来修改评分/Prompt 语义需更新版本，并明确旧排队任务处理。Provider 参数变更后不会偷偷用新模型运行旧任务。长期 Opportunity 归因与平台实际发送简历版本在后续阶段实现。
