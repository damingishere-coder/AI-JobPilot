# P1.2：求职机会与历史事件

## 交付边界

复用现有四张平台岗位表、`delivery_attempt`、分析和档案；V23 增加 `opportunity` 与 `opportunity_event`。不增加第二套 Application、公司或招聘者实体。

调整计划的依赖：真实网站 Smoke 继续阻止启用 BOSS/智联新 Runtime；本轮仅被动记录现有稳定链已经接受的事实，并提供人工 CRM 编辑，因此可以先实施。**Phase A 尚未验收完成**，本轮不会开启执行开关、发送消息或触发 AI。

## 身份、状态与事件

- 唯一身份：档案 + 平台 + 稳定岗位键。不同平台不自动合并。
- 求职阶段、兴趣、最新 Attempt 状态分别展示。AI 分析不改变用户兴趣；UNKNOWN 不推进已投递；迟到回调不能降低阶段。
- SQL 触发器在现有入库和 Attempt 事务里同步写入机会与事件，避免在各平台重复一套写入逻辑，也避免内存通知丢失。终态仍由现有 DeliveryAttemptService 校验证据。
- 分析结果事件引用不可变分析记录；新投递请求冻结当时分析 ID，后续回调复用该引用，平台实际发送的简历版本仍未知。
- 手工修改使用版本 CAS、操作幂等键和请求摘要。结果回退需选择原事件并填写更正原因；更正追加，不覆盖历史。备注、下一步事项、更正原因使用现有本地密钥加密。
- 当前详情展示最近 200 条事件和最近 20 次分析，投递记录保留。完整记录仍在库中；后续工作台增加分页。

## 归档与兼容

原 BOSS/智联“清空分析”接口保留，但改为归档可识别机会，底层岗位、AI 任务、分析、草稿和投递记录不删除。列表/统计排除归档机会；`/opportunities` 的“已归档”列表可恢复。重扫不会重置兴趣、阶段或归档状态。

缺少稳定键/档案的历史行原样保留，不强行归档或绑定；这些异常行可能继续出现在旧列表。执行中或 UNKNOWN 任务阻止归档/档案删除；已归档岗位拒绝新投递请求。数据库也阻止旧版本直接删除已关联的岗位和分析，因此旧程序不能绕过新历史保护。

## Migration 与回退

V23 是追加 Java migration，兼容 V1–V22。有效历史岗位回填为 `LEGACY_IMPORT`；源岗位已被删但 Attempt 身份有效时建立最小机会。历史事件发生时间、分析/实际投递简历版本不猜测；已有联系不算新投递。

发布前在空库、构造 V22 库、一致性生产备份副本演练，检查旧表行数、完整性、外键、幂等与孤儿。禁止以新表数量等于岗位数作为唯一成功依据。

回退优先关闭新页面入口，保留新表、新列和事件；不恢复旧数据库覆盖新事实。启用 V23 后旧清空逻辑会被触发器拒绝，须前滚修复或关闭清空入口，不能移除保护来强行兼容。

## 验证

自动化：OpportunityStageTest、OpportunityServiceTest、OpportunityMigrationTest、AnalysisClearSequenceSafetyTest、ProfileServiceAiTaskSafetyTest、DeliveryAttemptServiceTest；现有全量 Java、前端、Chromium 回归；静态导出/typecheck/lint。

人工本地验收：打开“求职机会”，选择虚构测试档案；记录兴趣/备注，归档后恢复，核对原平台列表。用两个窗口保存同一记录，后提交应提示刷新；UNKNOWN 不能归档。真实档案仅查看，不以修改真实结果进行回归。

PASS：身份不重复，未知不冒充成功，历史不被清空，错误归属/版本冲突被拒绝，恢复不触发投递或 AI。任一不满足即 FAIL。
