# 前端工作区重构交付与验收说明

本轮围绕求职流程整理导航、档案范围、表单和结果展示。最终测试结果、提交、PR、CI 与部署记录由交付负责人另行补充；本文件不代表已完成真实业务验收。

## 八个导航入口

| 入口 | 路由 | 职责 |
| --- | --- | --- |
| 工作台 | `/` | 汇总需要处理的事项，进入对应机会与记录 |
| 岗位发现 | `/discover` | 搜索条件、采集任务、岗位结果，BOSS 与智联切换 |
| 求职机会 | `/opportunities` | 机会列表、推荐机会；详情包含概览、反馈、面试、记录 |
| HR 沟通 | `/hr` | 沟通待办、托管规则、执行进度与回复结果 |
| 面试 | `/interviews` | 面试时间、轮次、准备事项与状态 |
| 策略复盘 | `/strategy` | 查看或生成复盘快照，保留反馈依据 |
| 求职资料 | `/profiles` | 档案、简历、求职目标和沟通资料 |
| 设置 | `/settings` | 环境、模型与连接配置 |

猎聘与 51job 放在次级“实验工具”，保留只读实验边界。统一壳负责档案选择与导航；手机使用抽屉，桌面侧栏可收起。

## 兼容路由与查询参数

- 标准岗位入口为 `/discover?platform=boss|zhilian&view=setup|task|results`，默认 BOSS 搜索条件。
- `/boss`、`/zhilian` 及各自 `/analysis` 保留；旧入口可进入统一工作区，不依赖新扫描事件才能查看历史结果。
- `/liepin`、`/51job` 及分析页继续保留。`/ai-config`、`/env-config` 复用资料与设置页；`/strategy/ranking` 继续可访问推荐机会。
- 工作区视图切换保留 `profileId`、`scanRunId`、`query`、`returnTo` 等既有上下文；切招聘平台时清除另一平台的 `scanRunId`。新任务成功启动后，任务范围更新为新批次。
- 机会页继续使用 `id`、`tab`、`view`、`archived`、`bucket`、`stage`、`platform`、`applicationStatus`、`q`、`page`。详情四页签切换保留草稿，工作台待办可进入对应记录页签。
- 保留参数不等于实现新查询能力：未新增按 `jobKey` 精确定位的 API，不宣称旧平台分析链接已定位单个岗位。

## 读取与操作契约

- 页面初始化、结果刷新、任务观察和历史展开沿用现有 GET 接口，包括档案、岗位列表/统计、AI 队列、采集记录和沟通活动；观察不会自动启动扫描、收费 AI、投递或回复。
- 列表 HTTP 失败、业务 `success=false`、响应格式错误均显示可重试提示；已成功加载的结果保留，并注明最近更新时间。迟到响应不得覆盖更新后的范围。
- 分页与导出使用“已应用”筛选，输入草稿仅在点击应用后生效。批量预览也读取已应用条件，保留下面的待确认状态约束。
- 现有写操作仍走原平台协议、权限检查、确认预览、任务预留和 runtime；不能因 UI 重构绕过平台预检或打开原本关闭的功能开关。
- 猎聘/51job 的队列刷新只执行 GET；实验能力不会升级为自动投递或 HR 自动发送。

## BOSS 批量范围

| 按钮 | 实际范围 |
| --- | --- |
| 预览全部 AI 推荐待确认 | 当前档案及扫描范围内的 AI 推荐待确认岗位；忽略列表筛选 |
| 预览当前筛选待确认 | 当前档案及扫描范围内的待确认岗位；应用已提交的地点、经验、学历、薪资、AI 分、关键词及猎头条件，包含其他页 |

两种批量动作的状态均固定为“待确认”；列表状态筛选不会改变发送接口的这个约束。范围常驻说明与按钮提示均明确这一点。预览展示逐条话术，用户确认后才创建投递任务；空预览不会发送。人工覆盖仍只处理明确勾选且具备链接的 AI 不匹配岗位。

## 草稿、冲突与未知结果

- 未保存的表单在离开或切换档案前受到保护；同工作区内部切视图尽量保留组件和草稿。原业务已有确认时不重复增加确认。
- 档案在其他窗口变化且当前有草稿时，显示冲突并保留草稿，不能默默用新档案覆盖旧输入。
- 求职机会、面试及托管策略沿用其版本校验。保存失败或版本冲突不清空输入；重复提交使用已有事件键/请求键，不盲目覆盖较新记录。
- 投递结果未知仍保留 UNKNOWN/待对账事实，先核对结果。明确重试继续使用原确认边界，不能把刷新或恢复页面当作重新发送许可。
- 现有档案写接口保存前通过 GET 核对当前档案；这只能阻止已观察到的切换，不能保证跨窗口 GET→POST/PUT 的原子性。GET 后另一窗口再次切档仍可能发生竞态。本轮不扩大档案后端范围，也不宣称此问题已由前端彻底解决。

## 验证方式与验收范围

从仓库根目录进入 `front` 后运行：

```powershell
npm run typecheck
npm test -- --maxWorkers=2
npm run lint -- app/boss app/zhilian app/liepin app/51job app/discover --quiet
npm run build
```

在仓库根目录运行适用的服务测试及已配置的离线浏览器回归：

```powershell
.\gradlew.bat test --tests "*InterviewServiceTest" --tests "*OpportunityWorkbenchServiceTest"
.\gradlew.bat browserRegressionTest
git diff --check
```

`browserRegressionTest` 需要已构建前端及已安装的测试 Chromium，具体依赖见 [离线浏览器门禁](browser-regression-gates.md)。本轮验收仅使用合成 fixtures、模拟 API、独立浏览器资料目录和临时数据库；请求默认拦截，不连接正式服务、真实招聘账号、招聘站点或收费模型。

离线界面需核对：八入口与当前项、桌面/手机导航、单个主标题、历史深链刷新、全部/本次范围、草稿保留、应用筛选后分页与导出、两种批量预览、详情展开、错误/空结果/旧数据状态及 UNKNOWN 恢复提示。不能通过真实扫描、投递、回复、上传简历或调用收费 AI 来验收本轮重构。

测试、构建和离线浏览器通过只证明对应实现与 fixtures，通过范围不包含真实网站动作。最终通过数量、未通过项与发布状态由交付负责人记录。
