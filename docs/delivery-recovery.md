# BOSS / 智联投递恢复

扩展版本 1.8.17，后台与页面协议 `2026-09-14-runtime-adapters`。

- BOSS 点击操作只触发一次 click，避免先派发 click 再调用 `.click()` 导致收藏切换两次、重复打开沟通入口或重复发送话术。
- 页面进入前进/后退缓存（BFCache）时立即撤销旧页面执行资格；返回页面后重新注入脚本，旧异步任务不得继续点击或填写话术。
- 若仍遇到跳转丢失回执，保持 UNKNOWN 并暂停，不把聊天页打开视为成功，也不自动重发。恢复时先只读核对首个岗位，再续投未触达项。

- 两个平台使用各自独立、非活动的投递标签页，不复用用户正在浏览的页面，也不置顶窗口。
- 智联分别读取按钮文本属性，识别“继续沟通”和“已向对方发送简历和打招呼语”。登录失效、验证、投递上限、未知结果和落库失败会暂停批量操作，剩余任务记录为未触达。
- 发送后的消息通道丢失不再自动重试。只读对账遇到登录失效也不会把历史未知结果变成可重发的失败。
- BOSS 用本人消息正文精确核验话术，排除“已发送”等状态文字。平台明确显示历史沟通时跳过发送，平台结果和 `NOT_SENT/ALREADY_CONTACTED` 话术证据分别保存。
- 岗位详情的 `startchat-content` 弹窗使用独立结构：只有平台发送回调赋予消息 ID 且状态为 `success` 的消息才计入精确确认；排除仍在发送、失败及初始化招呼。
- 分析页的“投递中断恢复”按投递日期显示当前档案已请求过的岗位；使用原确认快照逐条续投，已确认项跳过，UNKNOWN/REQUESTED 只读核对。恢复接口校验操作令牌、档案、最新 attempt、BOSS 自带招呼确认和话术规则。
- 暂停按钮在当前岗位结束后生效。恢复期间保持工作台打开；刷新或关闭后可以重新读取记录，但不确定结果不会自动补发。过期/关闭岗位、登录验证和平台额度不能伪报成功。

验证：扩展全套 `node --test chrome-extension/tests/*.test.cjs`；前端 `pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm build`；后端 `DeliveryAttemptServiceTest` 和 `ZhilianDeliveryControllerTest`，并运行 CI。

部署沿用已有 6866 服务和共享数据库。备份当前运行提交、构建资源、扩展与数据库后更新；Chrome 中需重新加载已安装的扩展，再刷新工作台。回滚代码/资源不覆盖已产生的投递事实或数据库。
