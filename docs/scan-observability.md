# BOSS / 智联扫描记录与控制

扩展 1.8.16 增加扫描协议 1；后端 V28 新增 `scan_run`、`scan_event`、`scan_command`。原有岗位、入库回执和 AI 队列保留。扫描结束不代表 AI 分析结束，暂停扫描也不暂停已经入队的分析。

## 使用

两平台工作台的“扫描记录”默认显示最近任务，可选择历史任务。新增入队数来自 `fresh_scan_receipt.accepted`，读取数、重复数、详情失败和 AI 状态单独显示。旧记录注明“未记录完整过程”，不推断当时的错误或成功状态。

暂停先保存请求，扩展在安全检查点保存断点后确认；继续需要扫描页在线、有效断点、相同档案及配置；停止先禁止后续入库，扩展退出采集循环后确认。离线时“请求已保存”不等于“执行成功”。停止约束已保存后允许登记新任务；旧请求仍标注等待执行，旧任务后续提交始终被拒绝，迟到回执不影响新任务。重新扫描使用新任务 ID；继续沿用 ID 并递增执行轮次。旧轮次上报不能覆盖新状态，旧轮次提交不能进入队列。

刷新、页面跳转后先同步控制约束。后端暂时不可用时保存断点并暂停；连接恢复只补传日志，必须明确点击继续。后台每 30 秒同步，扫描页每 10 秒心跳；90 秒未联系显示状态待核实。后台联系不会冒充扫描页响应。Chrome 可能延迟后台闹钟，界面以实际收到联系的时间为准。

升级时先发布后端，再重新加载项目 `chrome-extension` 目录对应的“投递牛马 Chrome Bridge”及招聘页面。旧扩展不能启动协议 1 任务；磁盘上的版本不能证明 Chrome 已加载该版本。Codex 浏览器控制连接故障不会影响接口查询已有记录。

## 本地接口

所有接口带 `platform=boss|zhilian` 和 `profileId` 查询参数，核对当前档案。写入需 `X-Local-Action-Token`，继续使用现有本地来源限制。

| 方法与路径 | 内容 |
| --- | --- |
| POST `/api/scan-runs` | `{runId}` 幂等登记；发启动消息前调用 |
| GET `/api/scan-runs` | 最近 50 个新协议任务和 20 个有入库回执的旧任务 |
| GET `/api/scan-runs/{runId}` | 状态、实际版本、联系时间、入库和 AI 统计、控制回执 |
| GET `/api/scan-runs/{runId}/events?after=0` | 每页至多 200 条，用最后事件 ID 增量查询 |
| POST `/api/scan-runs/{runId}/sync` | 事件、页心跳和执行回执；返回当前约束和待执行指令 |
| POST `/api/scan-runs/{runId}/commands` | `{id,kind: PAUSE|RESUME|STOP}`，指令 ID 幂等 |
| GET `/api/scan-runs/{runId}/diagnostics` | 脱敏 JSON；最多 10000 条，截断时给出 `truncated/nextCursor` |

事件按 ID 去重，轮次内按序更新状态；迟到事件留在时间线，但不倒退状态。扩展先保存本地待发送队列，收到确认后移除；后台重启可重放事件和回执。每轮缓冲上限 500 条，关键记录无法写入时暂停并报告日志积压；历史后端记录不自动删除。

诊断字段采用白名单：阶段、关键词、计数、固定错误代码、版本、时间和控制状态。丢弃任意错误正文、堆栈、URL、Cookie、Token、完整 JD、简历、聊天、原始网页和响应。不提供截图或录像。完整原始采集数据仍沿用原来岗位处理链，不进入新的诊断日志。

## 验证与发布

- `node --test chrome-extension/tests/*.test.cjs`：离线持久队列、重放、旧执行器拒绝、断线恢复、缓冲上限、暂停保存失败和停止回执。
- `pnpm --dir front test`、`typecheck`、`lint`、`build:prod`：界面状态、刷新恢复、控制请求和原有采集页面回归。
- `gradlew.bat test`：SQLite 状态、轮次、入库限制、鉴权、档案隔离与旧任务兼容。
- `gradlew.bat browserRegressionTest`：新增扫描测试使用本地样本、真实 HTTP / SQLite、真实上报与控制模块和模拟 AI，验证双平台入库回执、继续轮次、停止执行回执及后台重建。测试网络不允许真实招聘平台或生产 6866。
- `P0_REHEARSAL_DB` 指向 SQLite 一致性备份后执行 `DatabaseMigrationRehearsalTest`，验证新增迁移及旧业务表行数。

正式部署沿用 `AI-JobPilot-worktrees/zhilian-modern-collection` 的 Alter Backend / 6866。部署前核对无活动扫描、无待执行 AI，并保存一致性数据库及旧版本依据。回滚恢复代码与静态资源，保留 V28 表和所有业务事实；有未完成控制请求时先确认执行器停止，不能用旧数据库覆盖新记录。

真实平台本轮仅允许读取版本、连接和状态。实际已加载扩展版本、下一次用户主动扫描的招聘网站效果及真实脱敏 Fixture 导出分别验收；离线通过不等于真实网站全流程通过。
