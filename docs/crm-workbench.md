# P1.4：求职工作台与事项聚合

首页先展示需要核对/确认/跟进的机会，再展示求职进度。原平台概览保留在可展开区域；BOSS/智联扫描、确认投递和 HR 发送不改。侧栏逐步按工作台、岗位发现、投递与对账组织，不增加空导航。

## 查询与范围

`OpportunityWorkbenchService` 使用同一组事项条件计算卡片和列表，按当前档案、未归档机会统计。最新 Attempt 状态与 Opportunity 阶段独立；分组可以重叠，不能相加冒充总机会数。

- UNKNOWN/失败：最新 Attempt 结果；真实重试和对账仍回到原平台入口。
- 待确认：源平台待确认，尚未进入后续求职阶段且没有请求中/未知结果。
- 已投待回复：已确认投递且尚无确认回复阶段，**不代表检查后确定没有回复**。
- HR 消息待核实：未被用户查看或对应会话的明确结果确认覆盖的消息观察。标记查看只覆盖已加载的观察 ID，新消息继续提示；不自动推进阶段。
- 到期待跟进：用户填写的跟进时间已到，排除已结束机会。
- 今日新发现：上海自然日，排除 LEGACY_IMPORT。其他卡片均为当前存量。
- 较高匹配待关注：尚未进入后续阶段、未表示不感兴趣，沿用 BOSS 75 / 智联 65 的旧综合分阈值；不是个性化回复概率。三维推荐在 P1.7。
- 面试阶段和面试邀请暂按已确认业务事实展示，已安排轮次与待准备事项在 P1.5。

首次加载或读取失败不显示伪造的零。首页每 30 秒只读刷新，可见页面才轮询；若其他窗口切换档案，不展示错误档案数据。

## 详情与 URL

`/opportunities` 的 bucket、stage、page、archived、id 均保留在查询参数中，兼容静态导出与刷新。归档切换清除原事项筛选，避免用户误以为历史消失。详情继续复用 AI/投递/反馈信息，增加用户跟进时间与消息已查看操作。时间线按事件 ID 加载更早记录，避免超过 200 条后无法查阅；查询继续按机会与当前档案校验。

本轮同时修复反馈时间边界：HR 回复可能发生在成功 callback 到达之前，归因下限使用已知请求发生时间，而不是 callback 到达时间。旧时间未知仍不猜测。

## 验证与回退

无新增 migration。已有可空 follow_up_at 与 Event 记录用于跟进、已查看提醒。

自动化：每张卡片与列表计数一致、上海日期边界/历史回填/档案隔离、已查看不隐藏后来消息、不自动确认结果、极端页码、URL 参数/刷新/归档切换、API 失败不当零；全量 Java/前端、typecheck/lint/静态构建与浏览器回归。

人工：从首页点 UNKNOWN 卡片，核对列表范围和数量；打开详情后刷新，范围与机会保持。用虚构记录设置跟进时间、标记消息已查看，观察后来消息仍提醒。生产仅只读核验，不能把更改真实结果作为测试。

回退首页入口到 LegacyDeliveryOverview，保留新跟进与已查看事件，不删除数据库事实；不改变已发布 Runtime 安全开关。
