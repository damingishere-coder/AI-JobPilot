# BOSS 一键后台托管

在「环境配置」保存沟通资料与 QQ 设置，核对当前人物档案及 Chrome 的 BOSS 求职者账号后，点击「一键开启后台托管」。首次开启默认处理普通对话和最近 15 天待回复会话，历史范围可选择 7、15、30 天；已开启的策略保留其原有范围。你已经回复且没有新提问的会话跳过，包含已发送“谢谢”等收尾回复。面试安排、薪资承诺、资料矛盾、读取不完整等事项交给本人处理。电话和简历使用各自的分享授权。

环境页和 BOSS 浮窗的回复记录默认折叠。浮窗每 5 秒核对扩展宿主与后端的同一会话绑定，显示保存的实际历史范围和上次刷新时间，暂停/恢复使用与工作台相同的后台托管控制；首次授权与账号重新确认仍在工作台完成。读取失败时不继续显示旧的“运行中”。开启按钮不可用时，环境页列出尚未完成的确认或保存步骤。

## 运行要求与状态

- Chrome Bridge 1.10.8、Chrome 132 或以上，以及本地 Backend 服务。
- 托管使用专用 BOSS 聊天标签。自动创建标签时不激活标签、不聚焦窗口，也不使用桌面鼠标键盘；可以继续在其他标签或应用工作。
- Chrome、电脑和 Backend 必须保持运行。后台标签被冻结、卸载、退出登录或遇到验证时会暂停；必须先恢复该标签或完成登录，再点击恢复。
- 扩展 `RUNNING` 和后端 `CHROME_BACKGROUND` 的真实页面心跳均正常时，工作台才显示托管中。扩展 Service Worker 定时器本身不代表网页在线。
- 后端或扩展工作进程重启后读取已保存的意图与进度，并重新校验页面。Chrome 整体重启后，若网页只提供账号显示名而没有稳定账号 ID，需要本人重新确认账号；同名不能证明同一账号。
- 「暂停」保留授权和进度，「停止」撤销托管授权。专用聊天页检测到人工输入、点击或滚动会暂停，避免覆盖人工操作。仅「查看托管聊天页」会主动显示聊天窗口。
- 列表采集保存会话所在的滚动位置；读取时先回到该位置，再核验唯一平台 UID，位置失效时进行有界搜索。定位超时保留目标重试，暂未找到时最多重查列表两次，找到多个相同 UID 时暂停并要求人工核验。
- 专用页的短等待由扩展后台完成，包括打开会话后的 3 秒等待，避免隐藏页面定时器被延迟。等待前后核对页面、账号、任务代次与操作时限；暂停或绑定变化会取消后续操作。

## 巡检范围

后台每 30 秒校验页面并处理待发送任务，一轮扫描完成后约 1 分钟检查未读；页面变化可提前触发检查。首次建立联系人摘要，每 30 分钟核对列表摘要，只有未读数增加、摘要变化或尚未处理的近期会话才进入正文读取队列。时间范围在打开聊天前按北京时间和保存的 7、15、30 天设置筛选，超期消息即使保留未读标记也不自动浏览；老联系人今天收到新消息仍会处理。

`NEW_ONLY` 首次只保存列表摘要，不打开历史会话；`RECENT` 首次只读取指定时间范围内的会话。已回复、已处理且摘要未变的会话后续直接跳过；列表无法判断最后一条的发送方时，首次可能读取一次，确认后保存结果。未知日期的已读历史不按今天处理，只有未读或已有摘要出现变化时才允许核验，后端继续执行原有时效和人工审核规则。

摘要保存为 SHA-256 指纹，不在扩展状态中保存聊天正文；日期标签从“今天”变为“昨天”不会导致重复读取。暂停、工作进程重启和恢复会保留摘要进度，停止后重新授权或更换档案会重建。升级前留下的正文读取队列先重建列表筛选，不直接继续打开旧目标；此前已完成基线的 `NEW_ONLY` 托管仍读取近期未读，避免升级时遗漏尚未处理的新消息。

旧“发送不明／阻塞”记录保持待核验，不再强制扫描全部会话。只有符合上述巡检范围的新变化会话可能执行其必要身份核验；发送不明记录仍禁止自动重发。

旧视觉记录不会一律阻塞其他新联系人。独立新会话须有真实平台 UID、联系人和公司、完整上下文和带唯一平台消息编号的来源轮；与每一条未核验旧记录的联系人及公司均不同，且正文没有复用其原来源轮，才能独立处理。页面未显示岗位名称时不补造岗位，也不因此拦截独立联系人；关联旧视觉身份时仍须完整岗位与原来源轮。同名、同公司、缺联系人身份、缺消息编号、上下文不完整或旧证据不可读取时继续只读。此检查不修改旧记录、不建立旧身份关联，也不重发发送不明记录。

已保存且仅被身份依赖拦截的快照，在原账号及原授权下满足上述证据条件后，可以恢复未完成的分析。原正文、历史范围和账号绑定不变；此恢复不续期页面观察、不释放旧发送不明记录，实际发送仍须再次读取真实页面的完整来源轮。

聊天页面板显示后台已保存但被拦截的快照数量，巡检运行时仍可看到“部分回复受阻”。`GET /api/hr-assistant/watch/captures?size=20` 只读取当前档案最近的已存快照，最多 50 条，包含原文和拦截原因；不会续期页面心跳、重试分析或发送。已过期正文只返回元数据。

用户明确要求复核指定历史消息时，可通过 `POST /api/hr-assistant/watch/captures/{id}/review` 创建一次性人工文字草稿。请求须带本地操作令牌和 `{expectedProfileId, expectedPolicyVersion, draft}`，且真实后台聊天页已经连接；只使用同档案、同账号、同授权的已存快照，不接受客户端拼造正文。此操作仅重审系统因历史范围跳过的来源，不修改永久 `NEW_ONLY` 设置、快照历史标记或长期个人事实；已有发送、人工跳过、旧复核、更新来源和未知卡片均拒绝。返回 `REVIEW_REQUIRED` 后仍使用普通发送接口，经真实页面重新读取完整来源轮和新增本人消息回执才能确认已发。

## 防重复发送

采集快照加密持久保存，后台分析独立于扩展的短请求。相同账号、平台会话 UID 和完整 HR 消息轮用于去重；当前页面绑定和完整来源轮在提交前再次核验。

每个发送命令只提交一次。提交前保存检查点，之后使用新增本人消息的完整正文和上下文核验结果。超时、页面变化或回执不明进入待人工核验，不自动重发。旧视觉会话需要完整身份和来源轮的只读关联，不能按联系人名字直接创建新的发送记录绕过去重。

文字发送兼容 BOSS 的 `div.send-message` 与原有按钮控件，只点击当前聊天区域内唯一且可用的真实发送按钮。缺少按钮时不写入输入框、不使用模拟回车；输入后按钮不可用时不触发发送。`GET /api/hr-assistant/proposals/{id}/delivery` 只读取当前档案的原发送检查点和错误原因，不返回租约或令牌，不续期页面、不重发、不修改发送不明记录。

## 验证

```powershell
node --test chrome-extension/tests/*.test.cjs
node scripts/validate-chrome-extension.mjs
.\gradlew.bat test browserRegressionTest bootJar --no-daemon
cd front
pnpm test
pnpm typecheck
pnpm lint
pnpm build:prod
```

扩展测试检查 inactive 标签、暂停竞态、持久恢复及未知结果不重发；隔离 Chromium 测试运行生产 DOM 脚本并验证正文、单次提交、回执和旧页面代次拒绝。无头浏览器不能代替真实 Chrome 隐藏标签的验收：最终须在正常 Chrome 中确认托管状态、真实聊天读取和新增本人消息，并同时检查当前活动页未变化。

## 更新与回滚

沿用现有 RunDock 的 Backend，保留数据库、配置和 HR 加密密钥，更新服务目录后重启同一服务。Chrome 中加载的扩展也须更新到同一版本并刷新工作台。

代码回滚使用任务 PR 的反向提交，Backend 和扩展一同回滚。V36 只添加加密采集队列、会话别名和发送检查点；正常回滚保留新增表及数据，不删除历史。仅在必要且获得数据恢复授权时使用部署前 SQLite 在线备份恢复数据库。

参考源码、固定提交和许可证见 [第三方代码说明](third-party-background-chat.md)。
