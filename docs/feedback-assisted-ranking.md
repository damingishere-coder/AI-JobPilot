# P1.7 三维推荐与偏好

入口：策略 → 三维推荐与求职偏好。默认为历史综合分排序，可先预览草稿，再主动保存并启用。只影响新推荐列表，不改既有平台扫描配置、确认批次和投递范围。

## 数据与评分

V27 只扩展现有 `ai` 的偏好 JSON、偏好版本和默认关闭开关，另在 `job_ai_analysis` 补充加密的、后端校验过的完整评分结果。旧 Provider 响应指纹不能复原评分维度，因此不回填旧记录的新 Fit，也不自动重跑 AI。

- Fit：复用原五项能力维度的权重和状态系数，排除地点/薪资维度并归一化；未知维度数量与置信度独立展示。缺完整维度或全未知时显示历史综合分，保留版本差异。
- Preference：用户明确选择岗位、城市、规模、行业、工作方式和薪资。仅已知项计算分数并显示覆盖数；未采集信息、含混薪资或区间部分重叠都待核实。当前无可靠工作方式字段，不从 JD 猜测。复用现有 SalaryParser，日薪不自动当承诺月薪。
- Opportunity Signal：使用最近 30 天内生成的真实反馈快照；对应组至少 20 个有效样本且观察覆盖 ≥50%。只显示有利/混合/不利/样本不足及依据，不显示个人面试概率。

顺序：硬约束冲突/未知层级 → Fit 每 5 分一组（旧记录保留综合分标签）→ 组内偏好 → 组内反馈信号 → 原始分及稳定岗位 ID。反馈不能将远低于匹配组的岗位推到高匹配组之前。保留全部候选供探索，没有静默过滤或自动投递。

排除已归档、不感兴趣、后续求职阶段，以及任何已有 REQUESTED/UNKNOWN/CONFIRMED 投递的机会。预览不写设置，保存带档案和版本检查，重复相同设置幂等；关闭恢复原综合分顺序，已确认批次不重新排序。

## 分析证据修正

BOSS 与智联均不把搜索关键词当岗位原文证据。新规则版本 `job-evidence-20260914-v2`，已有分数和话术不改写。部署前排空正常 AI 队列；旧冻结任务规则不兼容时明确停止调用，不能偷换输入规则。

评分结果采用现有本地加密能力，不把简历引用或完整敏感资料发给排序 UI 或写进日志。排序页面只接收分数、版本、未知项和非敏感来源摘要。

## 验证与回退

临时库测试：偏好隔离、版本冲突、相同设置幂等、预览零写入、旧 AI 配置更新保留偏好、加密维度、未决投递排除。纯测试：未知/部分薪资、旧分回退、地点与 Fit 分离、样本不足无加成、匹配分组边界。Mock AI 检查 BOSS 关键词不能证明实际岗位要求。

前端：预览与保存分离、主动关闭、typecheck/lint/build；全量 Java 与副本 V27 migration 演练。真实数据验收只查看默认关闭状态与候选，不替用户设置偏好或投递。

回退关闭推荐开关/入口，保留 V27、偏好与分析历史。AI 安全证据修正保持，旧冻结任务不能由旧二进制混用新规则。Runtime 真实网站门禁独立保留。
