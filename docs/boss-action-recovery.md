# P0.4 BOSS 执行领取与恢复

## 发布状态

实现默认关闭的持久执行路径，开关为 `application.runtime.boss-enabled=false`（Spring 环境变量 `APPLICATION_RUNTIME_BOSS_ENABLED`）。必须完成离线浏览器回归和用户确认的单条真实 Smoke 后才能作为默认路径启用。关闭时仍使用既有执行器；已领取的请求不会因关闭而降级重发。

扩展 1.8.11；background `2026-09-14-runtime-claims`；BOSS content `2026-09-14-boss-runtime`。三端版本一起更新。启用时后端拒绝不声明 Runtime 能力的旧客户端派发。

## 执行边界

人工确认产生原有 Attempt/话术快照。新请求标记 NOT_STARTED；导航前后端再次核对档案、最新 Attempt、岗位 URL、原话术，原子领取为 CLAIMED，固定 runId、runtimeSessionId、correlationId 和 claimVersion。

页面确认目标岗位、登录/风控状态、历史沟通之后，在“感兴趣/收藏/沟通”的第一次可能副作用之前签发一次性许可，持久化 EFFECT_POSSIBLE。重复领取、重复许可、旧执行者、程序重启均不能再次签发。许可接口不做网络重试；响应丢失只读核对。领取失败也不降级旧执行器。

许可返回后再核对页面身份和阻碍；工作台在领取前或许可前关闭都会停止。已开始的当前岗位允许收尾；不会自动续投下一岗位。页面正常读取继续复用已有有界导航和 DOM 等待；没有新增无限重试。

恢复列表可暂停已领取的批次，RUN_PAUSED 事件持久化；未签发的当前许可和同 runId 后续领取都会拒绝，重启不清除暂停。旧批次不自动恢复；未决请求先核对。`/api/delivery-attempts/runtime-capabilities` 显示当前开关状态。

已有沟通不发送话术；UNKNOWN 不重发。结果仍由 DeliveryAttemptService 原有证据/CAS 接受。新增 SQLite trigger 将结果事件与状态写回放在同一事务；重复回调不增加事件，写回失败一起回滚。签发过许可后，迟到 PRE_ACTION_ERROR/BATCH_HALTED_BEFORE_ACTION 不能把它写成可重试失败。

## 数据与隐私

V21 仅追加 Attempt 字段与 runtime_event。历史行/旧二进制写入默认为 LEGACY，不能猜测未执行；旧执行器领取后同样记 LEGACY，防止升级时误续投。新行保留原终态 CHECK，不替换平台表。

事件只存关联 ID、动作、阶段、页面类型、阻碍、已校验证据枚举、检测器版本、计数与服务器 UTC 观察时间。不会保存 URL 参数、Token、Cookie、正文或招聘凭据。Observation 是诊断信息，不能自行推进投递结果。当前记录领取、首次副作用许可、结果观察、结果接受及人工核对请求；导航内部每次等待尚未拆成独立事件，不宣称已覆盖所有 DOM 动作。

恢复列表显示阶段和执行时间线；REQUESTED/UNKNOWN 仍只读核对。已领取/结果未知记录阻止档案强制删除；明确删除已完成档案时影响预览计入执行事件，先删事件再删 Attempt，不产生孤儿。

## 验证与回退

- Java：临时 SQLite 并发许可、重复领取、重启、关闭开关、档案变化、迟到回调、观察去重、V20→V21 保留状态；既有迁移副本演练。
- Extension：许可网络丢失仅一次调用、不执行页面动作；工作台关闭、重复领取阻断；既有批次停止测试。
- DOM：真实 content 函数在许可拒绝/未知时点击数为零；登录和风控优先。
- 手动：隔离环境开启开关并注入断线；重启后恢复列表保持未决状态。真实网站仅用户确认一个指定岗位；成功证据与 Attempt 一致后记录 Smoke。此次自动化不登录招聘网站、不投递、不调用真实 AI。

回退先关闭开关，保留 V21 数据。未决已领取请求只核对，不交回旧执行器。不要用旧数据库覆盖新的业务事实。包含 V21 的新安全保护启用后，旧二进制不能直接恢复写入；必要时暂停执行并前滚修复。不存在删除历史数据的 down migration。
