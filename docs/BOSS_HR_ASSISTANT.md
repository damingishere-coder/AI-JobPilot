# BOSS HR 半自动回复助手

这个功能在你主动开始值守后运行，检查 HR 未读消息并生成回复草稿。手动确认模式等待你确认；授权托管模式由独立审核决定是否发送，遇到资料不足、风险或发送结果不明时停止自动处理。后台值守设置见 [后台托管说明](boss-background-hosting.md)。

## 回复方式

- 先回应 HR 本轮问题，通常一两句；简单招呼只回应招呼，不追加岗位、薪资或地点追问。
- 对方连续发来的问题合并处理，有必要才追问一个影响当前交流的问题。本人已问过或 HR 已回答的内容不再问，也不自动催回复。
- 本轮只有“好的”“收到”“谢谢”等结束语时通常不回复；纯婉拒、暂无合适岗位或人才库通知沿用“好的，谢谢”，随后结束。
- 生成和独立发送审核使用同一套对话规则。程序另外拦截重复问题、招呼后的岗位审问及婉拒后的继续争取；自然寒暄无需编造简历证据，个人事实、数字和承诺仍需逐句核验。
- 无法确认发送结果的记录继续冻结，不随话术更新重新发送。
- 本项目的 AI 功能统一使用 GPT-6.1（gpt-6.1-sol）：HR 草稿生成、发送审核、聊天图片识别、岗位匹配分析、打招呼文案、简历图片识别/复核、求职配置和搜索关键词生成、测试聊天。沿用已有 Codex CLI 登录；HR 调用不可用时停止处理并转人工，不降级到其他模型。婉拒致谢、去重、身份核验和发送确认仍由程序规则参与；PDF/Word 使用本地解析，语音仍需人工处理。

## 首次准备

1. 保持 AI-JobPilot 后端运行，并在 Chrome 中登录 BOSS，打开 `https://www.zhipin.com/web/geek/chat`。
2. 在 `chrome://extensions` 重新加载本项目 `chrome-extension` 目录，然后刷新 BOSS 聊天页。HR 值守由“投递牛马 Chrome Bridge”直接连接当前标签页，不需要 OpenCLI 或其他 Browser Bridge。
3. 如需 QQ 通知，启动 NapCat，在 OneBot 网络配置中新增 WebSocket 服务端：
   - 地址只用 `127.0.0.1`
   - 建议端口 `3001`
   - 设置独立 Token
   - 关闭 `reportSelfMessage`
4. 在投递牛马工作台的“环境配置”页面找到“BOSS HR 值守与 QQ 通知”，选择当前人物档案和“私人 QQ”或“指定群聊”，填写真实资料。Token、目标 QQ/群号和操作人 QQ 不会在读取接口中明文返回。

## 使用方法

- 点击 BOSS 页面右下角助手浮窗里的“开始值守”时，当前 Chrome 标签页必须是 BOSS 求职者聊天页。扩展只绑定这个标签页，不会新建窗口或打开 `about:blank`。浮窗只保留状态、值守控制和待确认回复，设置统一由工作台管理。
- 页面出现待确认草稿后，可以修改并保存、确认发送或跳过。编辑后的内容必须先保存，页面才会重新开放“确认发送”，避免确认文本与实际发送文本不一致。
- 高价值消息可以通知到指定私人 QQ 或指定群聊。私人 QQ 模式下，只有该 QQ 发来的命令会被接受：
  - `详情 1234`
  - `修改 1234 新的回复内容`
  - `发送 1234`
  - `跳过 1234`
- 群聊模式需要同时配置目标群号和“群内操作人 QQ”才能在群里执行上述命令；系统必须同时核对群号和发言人 QQ。操作结果会私聊返回操作人，避免在群里继续展示 HR 详情。
- 群聊模式不填写操作人 QQ 时是“仅通知”模式：群成员发出的任何命令都不会执行，请回 BOSS 页面处理。
- 确认码 15 分钟后失效；HR 新发消息或草稿版本变化后，旧确认也会失效。

## 安全边界

- OpenCLI 已退出 HR 正式值守、读取和发送链路，仅可由开发者另行用于诊断；本项目不会升级、卸载或修改本机 OpenCLI/Browser Bridge。
- 扩展使用 DOM 选择器定位当前会话、填写 `#chat-input`、触发发送，并再次读取聊天历史确认。
- 任何会话映射不唯一、验证码、登录失效、风控、页面结构变化或发送证据不完整都会停止处理。
- `SEND_UNKNOWN` 表示可能已经发出，系统不会重试。
- 后端保存的聊天正文、草稿、确认码、HR/公司/岗位、外部 UID、QQ Token、目标 QQ/群号和操作人 QQ 使用 AES-256-GCM 加密；用于去重和定位的索引采用密钥化 HMAC。扩展 Outbox 只暂存 `captureId`、稳定 UID 和未读数，不保存姓名、公司、岗位或消息正文。30 天后会删除消息正文并擦除旧会话身份、草稿、确认码和发送证据，只保留分类、状态、置信度等匿名统计。
- BOSS 对未经授权插件、自动获取及自动操作有限制。启用前请自行确认账号和平台风险，程序不会绕过验证码或风控。

首次真人验收只做“发现未读 → 生成草稿 → 页面/QQ 展示”。只有你针对某一条任务再次确认“发送”后，才执行那一条回复。可同时参考 [BOSS 用户协议](https://www.zhipin.com/web/common/protocol/protocol-2019-09-30.html)、[NapCat 网络配置](https://napneko.github.io/onebot/network) 与 [OneBot API](https://napneko.github.io/onebot/api)。

## 本地配置项

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `APP_HR_MAX_CONVERSATIONS_PER_SCAN` | `100` | 单轮安全上限 |
| `APP_HR_KEY_PATH` | `%LOCALAPPDATA%\AI-JobPilot\secrets\hr-chat.key` | 加密密钥路径 |

不要把密钥、Token、Cookie、QQ 号或群号写入仓库或公开截图。


## 值守版本与人物档案（2026-09-06）

- 环境配置顶部提供“打开 BOSS 聊天页”，优先聚焦已绑定标签，其次复用聊天标签，否则新建固定 BOSS 聊天地址。打开页面不会自动启动值守或发送。
- AI 调用方式、模型和密钥全局共用；简历、沟通资料和 QQ 设置按人物档案保存。切换档案不会切换浏览器 BOSS 账号，开始值守前必须核对两者。
- 值守期间后端拒绝切换或删除当前档案，返回 HTTP 409 / `HR_WATCH_ACTIVE`。先停止值守；采集入库和已领取发送命令完成前仍不可切换。未知发送结果不自动重试。
- 扩展 Outbox 增加档案和会话归属，只重放当前档案记录。旧版缺少归属的记录保留并提示人工处理，不能自动分配给新档案。
- `/api/ready` 正常只表示基础服务健康。必须同时确认 `/api/hr-assistant/status` 返回成功；404 说明运行的后端缺少值守功能，应检查 6866 监听进程及其工作目录。
- 同一次发布必须包含后端、前端静态资源与 Chrome 扩展 1.6.1。更新后刷新扩展、工作台和 BOSS 聊天页，避免旧内容脚本继续运行。
